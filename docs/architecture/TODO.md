# LibrePaint全面改造TODO

## 目的

この文書は、LibrePaintのコード配置、テスト基盤、描画基盤、描画バックエンド、モバイルUI、コード品質を段階的に刷新するための全プラットフォーム共通ロードマップである。各プラットフォーム固有の実装項目と検証記録は、`docs/<platform>/`の文書で管理する。

ここでいうパッケージングは、C++のクラス、名前空間、ライブラリー、プラグイン、ディレクトリーを責務単位へまとめるコード設計を指す。

## 進行方針

- 各段階は、現状調査、設計記録、実装、移行、退行検査の順で進める。
- 後続段階の調査と試作は先行できるが、本実装は依存する前段階の完了条件を満たしてから統合する。
- R2で現行挙動を固定するまでは、描画アルゴリズム、実行順序、同期方法を変更する最適化へ着手しない。
- 新しい生成、検査、計測、ベンチマークの各ツールはNix開発シェルへ固定し、ローカル環境への個別導入を前提にしない。
- 性能改善は計測条件、基準値、変更後の結果を同じ形式で保存し、再現可能な比較を完了条件に含める。
- 大きな設計境界の変更は、実装前に責務、依存方向、移行手順、旧経路の削除条件を設計記録へ残す。

## R1: コードパッケージングの改善

### 目標

名前と実際の責務が一致するコードパッケージを設計し、関連する処理を凝集させる。クラスを探すときに、機能の所有者からディレクトリーとCMakeターゲットを予測できる構造へ移行する。

### タスク

- [ ] 全CMakeターゲット、公開ヘッダー、主要クラス、プラグインの依存グラフを生成する。
- [ ] 各ディレクトリーとライブラリーについて、現在の名前、実際の責務、公開API、依存先、利用元を棚卸しする。
- [ ] `libs/ui`にある`KisApplication`、`KisDocument`、`KisImportExportManager`など、画面表示以外のアプリケーション調整、文書管理、入出力調整を担うクラスを全件分類する。
- [ ] `libs/ui/tool`に混在する画面部品、入力解釈、ストローク生成、描画処理を分類する。
- [ ] アプリケーション、文書、入出力、入力、ツール、キャンバス、描画、リソース、プラグイン基盤の責務と依存方向を定義する。
- [ ] 新しいディレクトリー、名前空間、CMakeターゲットの対応表と段階的な再配置計画を作成する。
- [ ] `kritaui`のように複数責務を持つ大きなターゲットを、循環依存を作らない凝集したライブラリーへ分割する。
- [ ] UIパッケージには表示、画面状態、ユーザー操作との接続を置き、文書モデル、ファイル入出力、描画ジョブを所有する処理を対応する非UIパッケージへ移す。
- [ ] 公開APIと内部APIを分離し、別パッケージから内部ヘッダーを直接参照する箇所を解消する。
- [ ] 互換用転送ヘッダーと一時的な接続層には削除条件を設定し、再配置完了後に除去する。
- [ ] パッケージ間の許可された依存方向を機械可読にし、循環依存と禁止方向への依存を継続検査で拒否する。
- [ ] 依存グラフ生成、ヘッダー依存検査、境界検査に必要なツールをNix開発シェルへ固定する。
- [ ] 再配置後の責務と調査入口をアーキテクチャガイドおよび図へ反映する。

### 完了条件

- [ ] 主要クラスの配置がパッケージ名と責務の定義から説明できる。
- [ ] UI、文書、入出力、入力、描画の各パッケージが個別のCMakeターゲットとして構築・検査できる。
- [ ] パッケージ間の依存が定義済みの一方向グラフを形成し、循環依存がない。
- [ ] 旧配置の転送ヘッダーと一時的な依存が削除されている。
- [ ] 新しい機能の所有者と最初に見る場所を、責務地図から一意に判断できる。

## R2: 現行挙動のテスト固定

### 目標

描画最適化で壊してはならない外部挙動、画素結果、実行順序、データ整合性を特性テストとして固定する。意図した仕様と偶然残った挙動を分類し、改造後の互換性を客観的に判定できる基準を作る。

### タスク

- [ ] 入力から表示までの現行経路と分岐を列挙し、各段階で観測可能な状態と不変条件を定義する。
- [ ] マウス、タブレット、タッチ、Pencil／スタイラスの押下、移動、解放、筆圧、傾き、合成イベントを記録・再生できるようにする。
- [ ] 代表的なブラシプリセット、キャンバス寸法、色深度、色空間、レイヤー構成、選択範囲、ミラー条件を固定した試験データを作成する。
- [ ] PaintOpの画素結果、ストローク補間、間隔、速度依存、筆圧依存、乱数シードを決定的に検査する。
- [ ] タイル更新、dirty領域、投影、キャンバス表示の各結果を段階別に検査する。
- [ ] ストロークの開始、ジョブ追加、終了、キャンセル、アンドゥ、リドゥの順序と最終状態を固定する。
- [ ] 複数レイヤー、マスク、フィルター、合成モード、ラップアラウンド、ミラー表示、複数キャンバスの基準画像を作成する。
- [ ] 描画中の保存、自動保存、文書切替、キャンバス終了、アプリ休止・復帰における整合性を検査する。
- [ ] 長いストローク、巨大ブラシ、高解像度画像、メモリー圧迫、ジョブ競合を再現する負荷試験を作成する。
- [ ] スレッド数とジョブ分割を変えても最終画素、アンドゥ履歴、文書状態が一致することを検査する。
- [ ] 完全一致が必要な結果と、色変換やGPU表示で許容差を認める結果を分類し、比較規則を固定する。
- [ ] 観測した現行挙動を、維持する契約、修正対象の既知不具合、未確定事項に分類する。
- [ ] 入力から表示までの遅延、フレーム時間、処理量、メモリー使用量を同じ試験データで記録し、最適化前の基準値にする。
- [ ] テスト実行、入力再生、画像比較、負荷検査、結果保存に必要なツールをNix開発シェルへ固定する。

### 完了条件

- [ ] 主要な描画機能について、最適化前の画素結果と状態遷移を自動再現できる。
- [ ] 変更後に維持すべき挙動と、互換対象に含めない既知不具合が明示されている。
- [ ] 並行実行、キャンセル、アンドゥ、保存、休止・復帰を含む試験が安定して反復実行できる。
- [ ] macOS、iOS、Linux、Android、Windowsで必要な共通試験と固有試験の対応表がある。
- [ ] R3以降の変更を判定する機能基準値と性能基準値が保存されている。

## R3: 描画の最適化

### 目標

R2で固定した挙動を維持しながら、入力から画面表示までの遅延要因を徹底的に計測する。局所的な高速化に留まらず、ストローク処理、タイル更新、投影、画面転送の責務と同期構造を再設計する。

### タスク

- [ ] R2の全特性テストを描画基盤変更の必須検査条件に設定する。
- [ ] 入力受信、ツール処理、ストロークキュー、PaintOp、タイル更新、投影、GPU転送、画面表示へ共通の追跡IDと計測点を追加する。
- [ ] 入力合成、キュー待ち、ロック競合、メモリー確保、画素コピー、dirty領域拡大、投影再計算、GPU待機を個別に計測する。
- [ ] `KisUpdateScheduler`、`KisStrokesQueue`、ストローク戦略の順序保証と排他条件を棚卸しする。
- [ ] CPUタイル、投影バッファー、GPU資源の所有権と寿命を明文化し、不要な複製と同期を除去する。
- [ ] dirty領域の伝播と合成依存関係を再設計し、変更範囲外の再計算と再転送を抑制する。
- [ ] 入力処理、ブラシ計算、投影、表示を安全に並行実行できるジョブ構造へ移行する。
- [ ] 実行中ジョブの優先順位と処理予算を定義し、入力への応答を背景処理より優先する。
- [ ] アンドゥ、キャンセル、ミラー表示、ラップアラウンド、複数キャンバスで同じ整合性を維持する。
- [ ] 変更単位ごとにR2の基準値と比較し、改善量と新たな律速箇所を記録する。
- [ ] 計測、追跡、ベンチマーク、結果比較に必要なツールをNix開発シェルへ固定する。

### 完了条件

- [ ] 入力から表示までの時間を処理段階別に再現可能な条件で説明できる。
- [ ] 対象端末ごとの遅延、フレーム時間、処理量、メモリー使用量の合格基準を満たす。
- [ ] R2で固定した画素結果、状態遷移、アンドゥ結果、保存結果の互換性検査を通過する。
- [ ] 性能退行が継続検査で検出され、基準を下回る変更を統合前に拒否できる。

## R4: Vulkanバックエンドの追加

### 目標

描画基盤と画面APIを分離し、共通のVulkanバックエンドを追加する。macOSとiOSではMoltenVKを介してMetal上で実行する。

### タスク

- [ ] キャンバス合成、投影転送、表示、色変換に必要な描画バックエンド契約を定義する。
- [ ] Vulkanへ移す範囲とCPU描画に残す範囲をR3の性能計測に基づいて設計記録へ固定する。
- [ ] Vulkanのインスタンス、物理デバイス、キュー、資源、同期、パイプラインの寿命管理を共通実装にする。
- [ ] macOS・iOS向けMoltenVK、Vulkan Loader、ヘッダー、シェーダー変換ツールをNix派生物として固定する。
- [ ] Linux、Windows、Androidでは各プラットフォームのVulkan実装へ同じバックエンド契約で接続する。
- [ ] SPIR-V生成、反射情報、シェーダー検査、キャッシュ生成を再現可能なビルド工程へ組み込む。
- [ ] タイル／投影の部分転送、ステージング資源、フレーム同期、パイプラインキャッシュを実装する。
- [ ] sRGB、広色域、HDR、高ビット深度、表示色変換の結果をR2の基準画像と比較する。
- [ ] デバイス喪失、アプリ休止・復帰、画面回転、サイズ変更、メモリー警告から安全に復旧する。
- [ ] Vulkanが利用できない環境向けの代替経路と、実行時の選択・診断方法を定義する。
- [ ] Vulkan検証層、シェーダーコンパイラー、GPU診断ツールを対象別のNix開発シェルへ固定する。

### 完了条件

- [ ] 同じ文書と表示条件で、Vulkan経路とR2の基準画像との差を許容範囲内に収める。
- [ ] macOSとiOSでMoltenVK経路を使用し、実機の描画、休止・復帰、回転を完走する。
- [ ] Linux、Windows、AndroidでVulkan経路を選択して主要描画シナリオを完走する。
- [ ] Vulkan検証層の重大な指摘がなく、GPU資源と同期の退行を自動検出できる。

- [ ] Pencil／スタイラス描画、指による移動・拡大縮小・回転、誤接触除去の入力規則を統一する。
- [ ] Safe Area、画面回転、分割表示、外部キーボード、システム文字サイズへ対応する。

- [ ] 休止・復帰、メモリー圧迫、GPU再作成中も編集状態と操作の連続性を維持する。
- [ ] アクセシビリティー、最小タップ領域、コントラスト、読み上げ順を自動・実機検査する。
- [ ] 画面検査、入力再生、実機ログ収集に必要なツールをNix開発シェルへ固定する。

### 完了条件

- [ ] 主要な描画、ブラシ設定、レイヤー操作、保存をペンとタッチ中心で完了できる。
- [ ] 対象iPadと代表的なAndroid端末で、回転、休止・復帰、分割表示を含む操作検査を完走する。
- [ ] モバイルUIの変更がデスクトップUIへ暗黙に波及せず、共通機能は同じアプリケーションAPIを使用する。
- [ ] 代表画面と入力手順の退行を自動検出できる。

## R6: 全面的なリファクタリング

### 目標

C++20を共通言語基準とし、不要な依存関係と歴史的な互換層を削減する。コード規約、依存方向、性能、安全性を機械的に監査できる保守基盤を確立する。

R1はコードの責務と配置を整える段階であり、R6はその境界を前提として言語機能、依存ライブラリー、実装様式、監査規則を全面的に整理する段階とする。

### タスク

- [ ] 全対象のコンパイラー、標準ライブラリー、Qt、CMakeが満たすC++20対応範囲を固定する。
- [ ] CMakeの言語基準と警告設定をターゲット単位で統一し、プラットフォーム別の例外を一覧化する。
- [ ] 所有権、寿命、NULL許容性、エラー表現、並行処理の規約をC++20の機能を用いて明確化する。
- [ ] 公開APIを維持する移行層と削除期限を定義し、内部実装を段階的に現代化する。
- [ ] ライブラリー、プラグイン、外部依存関係のグラフを生成し、循環依存と逆方向依存を検出する。
- [ ] 各外部依存関係について利用機能、代替可能性、バイナリー容量、更新負担、安全性を評価する。
- [ ] 未使用・重複・置換可能な依存ライブラリーと互換層を削除する。
- [ ] コーディング規約を更新し、整形、静的解析、ヘッダー依存、未定義動作、スレッド安全性の検査を自動化する。
- [ ] アーキテクチャ境界、公開API／ABI、プラグインメタデータ、ライセンス、安全性の監査条件を継続検査へ追加する。
- [ ] 例外抑制には所有者、理由、対象範囲、削除条件を必須とする。
- [ ] 整形、静的解析、依存解析、監査に必要な全ツールをNix開発シェルへ固定する。

### 完了条件

- [ ] 全対象プラットフォームが共通のC++20設定で構築される。
- [ ] 依存方向と公開境界への違反を統合前に検出できる。
- [ ] 外部依存関係の削減結果と、残す依存関係の所有者・用途・更新方針が記録されている。
- [ ] コーディング規約、静的解析、単体試験、性能試験、安全性監査をNix開発シェルから再現できる。
- [ ] R1～R5で導入した旧経路と移行層が、定義済みの削除条件に従って整理されている。

## 全体完了条件
