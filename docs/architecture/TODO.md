# LibrePaint全面改造TODO

## 目的

この文書は、LibrePaintのコード配置、テスト基盤、描画基盤、描画バックエンド、モバイルUI、コード品質を段階的に刷新するための全プラットフォーム共通ロードマップである。各プラットフォーム固有の実装項目と検証記録は、`docs/<platform>/`の文書で管理する。

ここでいうパッケージングは、C++のクラス、名前空間、ライブラリー、プラグイン、ディレクトリーを責務単位へまとめるコード設計を指す。

## 進行方針

- 各段階は、現状調査、設計記録、実装、移行、退行検査の順で進める。
- 後続段階の調査と試作は先行できるが、本実装は依存する前段階の完了条件を満たしてから統合する。
- R2で現行挙動を固定し、その基準を入力として描画アルゴリズム、実行順序、同期方法の最適化へ進む。
- 新しい生成、検査、計測、ベンチマークの各ツールはNix開発シェルへ固定する。
- 性能改善は計測条件、基準値、変更後の結果を同じ形式で保存し、再現可能な比較を完了条件に含める。
- 大きな設計境界の変更は、実装前に責務、依存方向、移行手順、旧経路の削除条件を設計記録へ残す。

## R1: コードパッケージングの改善

### 目標

名前と実際の責務が一致するコードパッケージを設計し、関連する処理を凝集させる。クラスを探すときに、機能の所有者からディレクトリーとCMakeターゲットを予測できる構造へ移行する。

### 長期構造ビジョン

UIはアプリケーションの利用事例の接続面を呼び出し、起動時の構成責務が
ドメイン実装とI/Oアダプターを登録する構造を目指す。ドメイン処理は、
ファイル、プロセス、ネットワーク、設定、時刻、乱数の各副作用を接続面の外側に分け、
値から値または実行指示を導く計算を独立して構築・検査できる境界へ進める。

このビジョンは各再配置の境界判断に用いる。R1は依存経路の一方向化、具体的な命名、
現存する関心領域ごとのパッケージ分割と集約を先に完了する。ロジック構造の再構築と抽象化は、
新しい所有境界から差し替え、I/O隔離、決定的試験、残る循環の必要性を確認した後に行う。
R1-G6e後半の実装順とYAGNIの適用は
[`document-package-boundary-plan.md`](document-package-boundary-plan.md)を正本とする。

### 実行ゲート

R1は次の順で進め、各ゲートの完了時に停止して成果物と検証結果を確認する。

1. **R1-G1 依存グラフ採取基盤**: CMakeターゲット、種別、定義場所、直接依存を同じ形式で再生成できるようにする。現状採取と再生成を担当し、依存規則はR1-G3とR1-G4が担当する。
2. **R1-G2 公開面と主要クラスの棚卸し**: 公開ヘッダー、主要クラス、プラグインの所有者、利用元、実際の責務を機械可読な台帳へ記録する。
3. **R1-G3 責務地図と依存方針**: アプリケーション、文書、入出力、入力、ツール、キャンバス、描画、リソース、プラグイン基盤の責務と許可依存を定義する。
4. **R1-G4 既存違反基準と継続検査**: 現在の循環、内部ヘッダー参照、逆方向依存を基準化し、許可グラフと診断規則を継続検査へ接続する。
5. **R1-G5 再配置計画**: 新旧ディレクトリー、名前空間、CMakeターゲット、転送ヘッダー、移行順、削除条件を対応表へ固定する。
6. **R1-G6 段階的なターゲット分割**: 特性試験が存在する責務から小さい単位で移動し、各単位で基準表を縮小する。
7. **R1-G7 移行層の削除と文書同期**: 旧経路、転送ヘッダー、一時依存を削除し、責務地図と調査入口を最終状態へ更新する。

### R1-G6e-P 文書パッケージ境界マイルストーン

R1-G6e後半は、依存方向を一方向にした後、文書状態、文書表示、文書ファイル保存という
現在存在する関心を、`kritadocument`、`kritadocumentui`、`kritadocumentfiles`へ集約する。
形式選択と形式変換は既存の入出力所有に維持する。

実装は、独立した文書UIファイルの一括移設、文書表示の構造分離、文書ファイル保存の構造分離、
残る境界の再評価の順で進める。差し替え要求のない汎用利用事例層、汎用永続化層、接続面、
アダプター、空ターゲットは作らない。各検査段階の起点、完了条件、検証範囲、中止条件は
[文書パッケージ境界計画](document-package-boundary-plan.md)に記録する。

- [ ] 全対象のコンパイラー、標準ライブラリー、Qt、CMakeが満たすC++20対応範囲を固定する。
- [ ] CMakeの言語基準と警告設定をターゲット単位で統一し、プラットフォーム別の例外を一覧化する。
- [ ] 所有権、寿命、NULL許容性、エラー表現、並行処理の規約をC++20の機能を用いて明確化する。
- [ ] 公開APIを維持する移行層と削除期限を定義し、内部実装を段階的に現代化する。
- [ ] ライブラリー、プラグイン、外部依存関係のグラフを生成し、循環依存と逆方向依存を検出する。
- [ ] 各外部依存関係について利用機能、代替可能性、バイナリー容量、更新負担、安全性を評価する。
- [ ] 未使用・重複・置換可能な依存ライブラリーと互換層を削除する。
- [ ] コーディング規約を更新し、整形、静的解析、ヘッダー依存、未定義動作、スレッド安全性の検査を自動化する。
- [ ] アーキテクチャ境界、公開API／ABI、プラグインメタデータ、ライセンス、安全性の監査条件を継続検査へ追加する。
- [ ] 例外抑制には所有者、理由、対象範囲、削除条件を必須とする。
- [ ] 整形、静的解析、依存解析、監査に必要な全ツールをNix開発シェルへ固定する。
