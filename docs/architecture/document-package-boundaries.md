# 文書パッケージの責務境界

## 目的と構成

文書状態、ファイル操作、画面表示を別の所有先へ置き、変更と検証の範囲を責務ごとに保つ。
文書全体の寿命と画像・アプリケーションの接続は`KisDocument`が調整する。

| 所有先 | 対象 | 責務 |
| --- | --- | --- |
| `libs/document/session` | `kritadocument` | 文書識別、変更状態、自動保存状態、回復状態 |
| `libs/document/files` | `kritadocumentfiles` | 保存先検査、バックアップ、自動保存名、回復候補の探索・読込・消去 |
| `libs/document/ui` | `kritadocumentui` | 履歴接続と表示、文書情報編集、読込・保存の表示と通知、回復候補の表示 |
| `libs/impex/metadata` | `kritaimpex` | 形式処理と文書表示が共有する直列化対象の文書情報 |

## 依存方向と所有

[文書状態のCMake定義](../../libs/document/CMakeLists.txt)はQt Coreだけを公開依存とする。
[ファイル操作のCMake定義](../../libs/document/files/CMakeLists.txt)はQt Coreを公開し、
全体基盤と資源ストレージを私有依存とする。文書状態とファイル操作は、表示部品を所有する
[文書UI](../../libs/document/ui/CMakeLists.txt)から独立して利用できる。
UIの各実装単位は、実際に利用する入出力エラー、メタデータ、取り消し履歴、Qt部品へ直接依存する。

形式選択と形式変換は既存の入出力パッケージが所有する。文書情報の直列化は形式処理と共有し、
自動保存中・変更済みなどの状態は呼出元から明示的な値で渡す。
回復候補の画像生成は文書側が行い、表示側は生成済みの`QIcon`を受け取る。
履歴との接続は`libs/document/ui/undo`が所有し、既存の`KUndo2Stack`と`KUndo2Group`を利用する。

## 維持する契約と保守

保存成功、警告を伴う成功、失敗、取消し、バッチ処理時の非表示、Qt通知順序を維持する。
保存先と内容URI、バックアップ世代、自動保存名、回復ファイルの消去はファイル操作の契約で検査する。
取り消し、やり直し、履歴通知、操作名、アクションの有効状態、回復候補の選択と破棄は文書UIが検査する。

具体的な所有者への直接依存を基本とする。新しい抽象は、複数の現行製品実装、値だけでは成立しない
決定的試験、要求された外部処理の差し替え、所有移動では解消できない循環の根拠がある場合に導入する。
同じ変更で製品利用元、実装、観測契約、所有寿命を定義する。

責務境界を変更するときは本書、CMake定義、`package-boundaries.json`を同期し、
対象CTest、影響範囲CTest、高速検査と該当プラットフォームの境界検査を行う。
作業状態と検証結果は対応Issueへ記録する。外部I/Oとの追加分離は
[Issue #48](https://github.com/serika12345/librepaint/issues/48)、決定的計算の試験は
[Issue #49](https://github.com/serika12345/librepaint/issues/49)が所有する。
