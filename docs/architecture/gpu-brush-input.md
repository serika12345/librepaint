# 筆圧と間隔からのGPUブラシ命令生成

位置と正規化した筆圧から円・楕円のブラシ印を作り、GPUの作業版へ入力順に渡す。
入力の分割、描画要求の拒否、形状の差し替えで、ブラシ印の配置と受理済みの編集を維持する。
画素の生成・保持はGPU文書が担当する。

## 所有と依存方向

| 所有者 | 責務 | 依存先 |
| --- | --- | --- |
| `libs/image/dabspacing/KisDabSpacing.*` | 等方的な距離間隔、区間内の補間係数、残距離 | Qt Core、実装内のQt Gui |
| `libs/image/kis_distance_information.*` | CPU描画の距離・時刻・描画情報 | 距離間隔の値計算、既存画像モデル |
| `libs/painting/gpu/KisGpuBrushStroke.*` | 筆圧からの大きさ、入力の補間、GPU向け命令と受理済み入力の進行 | 距離間隔の値計算、GPU編集セッション |
| `libs/image/gpu/KisGpuEditSession.*` | 作業版、確定・取消し、履歴、受理済み命令からの回復 | GPU文書タイル |

`kritaimagedabspacing`はCPUとGPU向け入力生成から共用する小さな値計算の所有者である。
`kritapaintinggpubrushstroke`はGPU編集セッションへ依存し、画像モデル全体、ツール、UIへの依存を持たない。
GPU向け入力生成は`LIBREPAINT_BUILD_GPU_DOCUMENT=ON`で構築する。

## ブラシと配置の契約

入力は文書座標の位置と0〜1の筆圧である。筆圧によるサイズ変化は線形とし、
一定サイズの設定も受け取る。直径・フェード・色・合成方式・不透明度・被覆率・質感強度は操作中に固定する。
フェードは0より大きく1以下、間隔係数は有限の非負数とする。

最初の入力へ一つの印を置き、その印の大きい方の直径と間隔係数の積を次の間隔にする。
最小間隔は0.5画素で、途中の入力区間に残った距離を次の区間へ引き継ぐ。
各印で位置と筆圧を線形補間し、その印の大きさから次の間隔を求める。
縦または横の直径が0.01画素未満なら印を生成しない。
同じ位置での筆圧変化は、次の移動区間の入力値として扱う。

距離計算は既存CPU描画と同じ単精度の区間長を使う。
`libs/image/tests/data/brush_spacing_contract.json`はCPU描画の補間・距離管理で確認する
配置データを持ち、中心と直径の許容差を0.00001画素と定める。
GPU試験はこの配置から直接生成したブラシ印と、入力から生成したブラシ印の最終画素を比較する。
円・楕円の形状と画素合成は[GPU文書タイルの契約](gpu-document-tiles.md)に従う。
ブラシ固有の非線形曲線、自動間隔、時間間隔、非等方的な間隔は、各比較契約で対象を拡張する。

## 編集操作への接続

利用側は`KisGpuEditSession::begin()`で操作識別子を取得し、そのセッションと識別子、
ブラシ設定、文書の切り詰め領域から`KisGpuBrushStroke`を構築する。
セッションの寿命は入力生成器より長く、全操作は同じ発行スレッドで実行する。

`append()`は前回受理した入力の続きから生成する。`replace()`は全入力を最初から生成し、
編集セッションの作業版を差し替える。各要求に不変の選択範囲を指定できる。
`Settings::texture`には、同じセッションで準備した不変の質感マスクを指定できる。
入力から生成した各印は同じ模様と原点を使い、模様の再転送を伴わずGPUで処理する。
`Settings::textureStrength`の0〜255を各印へ渡し、形状・模様・強度の三項積を
不透明度と選択より先に適用する。強度の伝達は直接生成した印との画像比較で検査し、
同じ値を差し替え、履歴と受理済み命令からの回復へ保持する。
確定・取消しと完了回収は編集セッションを通じて行う。
確定は表示済みの作業版を採用し、ブラシ印を再生成しない。

`Settings::smudgeRate`は0〜255の下地混色率である。各印は直前に生成した印の中心を
整数画素へ切り下げて採取し、最初の印は自分の中心を採取する。採取位置は
受理済みの入力進行に含め、要求拒否で保持し、差し替えで最初から作り直す。
下地混色は[GPUブラシの下地採取](gpu-brush-mixing.md)の画像・発行条件に従う。
一要求の混色印は最大16個とし、超過は`InputLimitExceeded`として全要求を拒否する。

入力列は`appendPartial(samples)`で一要求の上限まで進める。
受理時の`Update::completedSamples`個を入力列の先頭から除き、未完の末尾を次回も渡す。
`Update::sampleComplete`は渡した入力列全体の完了を表す。
区間内の位置・筆圧・残距離・採色位置を受理した印まで進め、全区間の一括生成と同じ印列を作る。
拒否時は進行を維持する。利用側は受理済みの入力点だけを除き、完了回収と交互に呼ぶ。
これにより混色の16印制限と通常ブラシの生成試行上限を保ちながら、長い移動を処理する。
長い形状を一括公開する利用側は、編集セッションの`beginReplacement()`と新しい入力進行を使い、
`appendPartial()`で非公開の作業版を生成する。全入力の処理後に`publishReplacement()`で
完成した画素と回復命令を同時に採用する。

レイヤー文書では`KisGpuLayerDocument::begin()`が返したセッションと操作識別子を使う。
利用側はブラシ入力生成器が借用する間、そのセッションの共有参照を保持する。
文書がレイヤーへの採用と全体の履歴を所有し、取消し・確定・終了後の操作識別子を失効させる。

入力数と印の生成試行数は、一回の要求ごとに構築時の上限を検査する。初期値は4096。
非有限の値、範囲外の筆圧、補間が進まない座標は`InvalidInput`、上限超過は
`InputLimitExceeded`としてGPU操作前に拒否する。
編集セッションが拒否した要求は`EditRejected`とその拒否結果を返す。
いずれの拒否も入力の進行と作業版を維持し、発行量を回収した後に同じ入力を再試行できる。

回復記録には受理したブラシ印、選択生成命令、質感の準備済みマスクと原点を保持する。
`progress()`は直前の受理済み入力、次の間隔、区間の残距離、下地採取用の直前の印位置をCPU値の`Progress`として返す。
この値はGPU資源とセッションの参照を持たず、入力生成器とGPUの終了後もコピーして保持できる。
要求の拒否は返される進行値を維持し、受理した`replace()`は差し替えた入力から進行値を作り直す。

GPU再作成時は、利用側が進行値と対応する文書回復値、同じブラシ設定を保持する。
借用中の入力生成器を終了し、編集セッションや旧GPU版への参照を解放して文書を一時停止する。
文書の再開が`Editing`へ到達した後、`currentEditing()`のセッションと新しい操作識別子、
保持した進行値を受け取る構築子で入力生成器を再作成し、`append()`で未受理の入力から継続する。
質感と選択範囲は保持したCPU資源から新しいセッション上に準備する。
進行値は同じ操作・設定・切り詰め領域に対応させ、描画命令の再生成を伴わず間隔と筆圧の補間を維持する。
進行値の寿命は実行中の入力操作に属し、回復ファイルは受理済みの描画結果を保持する。

## 保守と検証

配置データはCPUの距離・描画情報とGPU向け入力生成で共用する。
配置規則の変更は両方の利用側、入力分割、受付拒否後の再試行を検査する。
GPU交換を挟む描画は、単色・質感・選択付きの追加と差し替えで、連続描画との画素完全一致を検査する。
`libs/painting/gpu/tests/KisGpuBrushInputWorkloads.h`は、画像契約と入力から表示までの計測で
初期レイヤー、ブラシ設定と位置・筆圧の入力列を共有する。
`KisGpuLayerBrushImageTest`は小負荷と24レイヤーの4096×4096文書で追加・差し替えを行い、
2回の準備更新と15回の入力更新後の投影を、固定したRGBA8画像のSHA-256と完全一致で比較する。
基準と採取条件は`libs/painting/tests/data/gpu_brush_input_contract.json`が所有する。
この契約は実表示と独立して実行し、通常操作中のCPU画素転送0も検査する。
構築・実GPU試験の手順は[開発手順](DEVELOPMENT.md#gpu文書タイルの検証)に従う。
