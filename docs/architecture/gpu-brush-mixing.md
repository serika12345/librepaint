# GPUブラシの下地採取

## 目的と所有

`libs/image/gpu/KisGpuDabMixing.cpp`は、GPU上の文書画素から色を取得し、
入力順に混色した作業版を生成する。ブラシ入力側は採取座標と混色率を値として渡し、
画像側が資源、順序、予算、完了までの保持を所有する。
`KisGpuBrushStroke`は直前の印位置をCPU値で保持し、編集セッションは受理済みの採取命令を
履歴と回復記録へ保存する。

## 画像と実行の契約

`DabCommand::pickup`は符号付き整数の採取画素と0〜255の混色率を指定する。
採取は同じ作業版の直前の命令までを読み、タイル境界や切り詰め領域の外側にも適用する。
未配置の採取タイルは透明とする。各印の前に4バイトをGPU内で複写し、
一つの計算パスで印を描画する。複数の印は一つの提出で順序を保持し、
変更タイルは一度だけ複製する。CPUへの画素転送は発生しない。

対象はRGBA8の一点採取、色の追加なし、アルファのロック解除を使う混色である。
採取色を`0.8 * rate / 255 * opacity / 255`の不透明度で下地へ通常合成し、
形状・被覆率・選択範囲のマスクを使うコピーで反映する。
8ビット乗算、整数の線形補間、アルファ付き色の丸めを既存のCPU演算に合わせる。
`libs/painting/tests/data/brush_mixing_contract.json`の480例は既存CPUの
`OverCompositor32`と`KoCompositeOpCopy2`を根拠とし、CPUとGPUの両方で完全一致として検査する。
浮動小数点の色補間は`fma()`で丸め順を明示する。

混色と通常の印・消去は同じ列に並べられる。混色する印の合成方式は通常合成に限る。
質感付き混色は、採取と質感の画像契約を分離して受け入れるため、この実行単位の対象から除く。
一点以外の採取範囲、色の追加、アルファのロックは、それぞれ画像契約を伴う実装単位で拡張する。

一要求は混色を含め最大16命令とする。印ごとの計算パスと時刻計測を一回の提出内に収め、
Metalの未提出パス数と発行量を制限する。超過、不正な合成方式、質感との組合せは
`InvalidCommand`として全要求を発行前に拒否する。
予算には変更タイル、命令、位置情報、4バイトの採取用領域、全パスの時刻計測を含める。
拒否は元の版と提出数を維持する。選択範囲が空なら元の版と完了を共有する。

## 寿命と検証

採取用の領域は提出の完了まで保持し、完了回収で解放する。統計`pickupCopyBytes`は
実際にGPU内で複写した採取画素を計上する。透明な未配置画素の初期化は複写へ含めない。
時刻を有効にした構成では、全印のGPU計算時間と読み取り量を集計する。

差し替えは確定前の版から再実行する。Undo／Redo、GPU再作成、休止復帰はCPUの採取命令を
同じ順に再実行し、作業版と確定版の画像を維持する。
復旧ファイルのバージョン3は採取位置と率を保存する。
検査はタイルをまたぐ依存、通常印との順序、選択、未配置の採取、容量不足、発行制限、
GPU喪失、差し替え、履歴、入力進行と復旧ファイルの往復を対象とする。
実行手順は[開発手順](DEVELOPMENT.md#gpu文書タイルの検証)に従う。
