# 複数文書のGPU寿命管理

## 目的と所有

`libs/document/gpu/KisGpuDocumentDevice.*`は、複数の独立したGPU文書が共有する
デバイスの寿命、終了、休止と再開を所有する。文書の画素・履歴・未確定入力は
`KisGpuLayerDocument`が所有し、この所有者は同じ文書を新しい保存領域へ再接続する。
文書側から画像側へ依存し、Qt Coreと具体的なGPU文書だけを使用する。

`kritadocumentgpudevice`は`LIBREPAINT_BUILD_GPU_DOCUMENT`が有効な構成で構築する。
デバイスの作成は最初の有効な文書作成まで遅延する。空の所有者の構築、休止・再開と
不正な回復値の拒否はGPU資源を作成しない。

## 利用方法と通知

1. 発行スレッドで所有者を作成し、デバイス全体の論理予算を渡す。
2. `createDocument()`または`restoreDocument()`に、文書のGPU・CPU予算、履歴数と発行数の上限を渡す。
3. 返された非零の文書識別子から`document()`と`store()`を取得する。零は拒否を表し、既存文書を維持する。
4. 表示側は`aboutToReleaseGpu()`へ直接接続し、描画側、投影、編集中セッションと画像へのGPU参照を解放する。
5. `suspend()`で全文書のCPU回復値を維持し、共有GPUを終了する。
6. `resume()`で一つの新しいGPUと文書ごとの保存領域を作り、`poll()`で各文書の復元を進める。
7. `gpuRestored()`で新しいデバイスと保存領域へ表示側を接続する。文書の画像は復元成功後に採用する。

全呼出し、通知の処理と破棄は同じ発行スレッドに属する。通知は資源を解放・再接続するために使い、
通知中の文書作成、終了、休止・再開は拒否する。借用した`device()`はGPU解放通知まで有効である。
モデルの共有参照は所有者より長く保持でき、所有者終了後はCPU回復値を保持した休止状態になる。
旧保存領域への外部参照はGPU終了で利用不能となり、新しい所有者へ渡す描画入力には使わない。

`closeDocument()`は対象文書の`documentAboutToClose(id)`を通知し、その文書を休止して管理から除く。
ほかの文書と共有GPUは継続する。終了・休止前の編集識別子は失効し、再開後は
`currentEditing()`の新しい識別子を使う。ブラシの入力進行は利用側がCPU値として保持する。

## 圧迫・喪失と失敗

`requestHistoryEviction()`は各文書のGPU過去版の解放を要求する。`poll()`で処理し、
復元や保守中の文書には、受理可能になるまで要求を保持する。現在の下地と作業版、
操作識別子、CPU履歴と受理済み入力を維持する。容量不足で拒否された入力は、解放後に同じ操作で再試行できる。

GPU喪失を検出した`poll()`は全文書を休止する。文書識別子、モデルの共有参照、
CPU履歴と作業中入力は維持し、明示的な`resume()`で復元する。
休止と履歴解放は新しい画素読取り・アップロードを発行しない。
GPUの再作成が失敗した場合は休止を維持し、`lastError()`に作成時の診断を保持する。
非同期の文書復元の結果は各モデルの`state()`と`recoveryError()`で取得する。
モデルごとの完全な復元と公開は画像側の文書契約に従う。

## 検証と保守

`KisGpuDocumentDeviceTest`は、独立した二文書の共有予算、未確定入力を含む一括休止・再開、
喪失後のCPU記録、対象文書だけの終了、所有者終了後のモデルの寿命を検査する。
全体予算を使い切った後に過去版を解放し、同じ入力を再試行して確定する。
構築と実GPU検査は[開発手順](DEVELOPMENT.md#gpu文書タイルの検証)に従う。
