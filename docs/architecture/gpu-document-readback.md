# GPU文書の固定版読取り

## 目的と構成

`libs/image/gpu/KisGpuDocumentReadback.*`は、確定済みレイヤー列のGPU版を固定し、
保存・書き出し用の完全なCPU画素を非同期に取得する。構築単位は`kritaimagegpudocument`で、
Qt Coreと具体的なタイル保存領域へ依存する。

入力の名前、識別子、順序、不透明度、合成方式、画素と任意のマスクを保持する。
結果は`KisGpuLayerDocument::Recovery`の一状態であり、画素とマスクは疎なRGBA8
チェックポイントとなる。保存時点のGPU結果を、入力命令の再実行から独立して固定する。

## 利用方法と寿命

1. 保存領域の送信スレッドで文書の`layers()`と`recovery().nextId`を取得する。
2. 同じ保存領域、レイヤー列、次の識別子とCPU上限をコンストラクターへ渡す。
3. `status()`が`Pending`の間、同じスレッドから`poll()`を進める。
4. `Succeeded`となった後に`result()`からCPU値を取得する。
5. 利用側の作業スレッドへCPU値を渡し、保存形式の処理を行う。

操作は保存領域を共有所有し、入力のGPU版を完了まで保持する。元の文書の編集、名前変更、
レイヤー削除と終了は独立して進められる。呼出しと破棄は送信スレッドで行う。
処理中の操作を破棄すると、結果の公開を取り消す。完成したCPU値は不変として扱い、
元のGPU、文書と読取り操作の破棄後も利用できる。

## 予算・処理順と失敗

CPU予算は、レイヤー記録、名前、各版のチェックポイントと処理中の座標・参照を発行前に
検査する。`reservedRecoveryBytes()`はこの論理容量を返す。実際のGPU読取り領域は
保存領域とデバイスのGPU予算へ含める。論理容量とプロセス全体の物理使用量は別の指標である。

同じGPU版を使う画素・マスクは一度読み取り、CPU値の参照も共有する。
一回の`poll()`で発行する読取りは最大一タイルであり、発行枠の不足は次の回収後に再試行する。
全タイルの成功後に完成値を一括公開する。空のレイヤー列も一状態として完了する。

`error()`は不正な文書、別の保存領域や未完成の版、CPU/GPU予算不足、GPU喪失と
読取り失敗を区別する。失敗は`Failed`となり、途中のCPU値と保持したGPU版を解放する。
`result()`は成功時だけ値を返し、再試行は新しい読取り操作で行う。
完成済みの値と成功状態は、後のGPU喪失でも維持する。

## 検証と保守

`libs/image/gpu/tests/KisGpuDocumentReadbackTest.cpp`は、読取り中の編集・文書終了、
複数レイヤーとマスク、共有版、CPU発行前検査、GPU予算不足、共有する発行枠、
部分読取り中のGPU喪失と別GPUでの画像完全一致を検査する。

`libs/document/files/gpu/tests/KisGpuDocumentRecoveryFileTest.cpp`は、取得済みの
GPU画素を背景保存し、元の文書とGPUの終了後に再読込する。描画命令を持たない
チェックポイントから、保存時点の画素とマスクを復元する。

タイル座標から画素領域への変換は`KisGpuTileGeometry_p.h`が所有し、編集回復、
チェックポイント集約と文書読取りで同じ整数範囲の検査を利用する。
