# GPU文書回復ファイル

## 目的と構成

`libs/document/files/gpu/KisGpuDocumentRecoveryFile.*`は、GPU文書のCPU回復値を
ファイルへ保存し、GPU資源と独立して再読込する。構築単位は
`kritadocumentgpurecovery`で、Qt Coreと画像側の具体的な回復値へ直接依存する。
`LIBREPAINT_BUILD_GPU_DOCUMENT`が有効な構成で利用できる。

画像側はレイヤー、画素・マスク、履歴、未確定編集とその再実行を所有し、文書ファイル側は
直列化、検査済みファイルへの置換と読込を所有する。標準文書形式の選択・変換は
入出力パッケージが所有する。

## 利用方法と寿命

1. 文書の送信スレッドで`KisGpuLayerDocument::recovery()`を呼び、CPU値を固定する。
2. 利用側が所有する作業スレッドで、保存先と固定値を`KisGpuDocumentRecoveryFile::write()`へ渡す。
3. `Error::None`の完了後に保存成功を採用する。元の文書の編集は独立して続行できる。
4. `read()`が返した`ReadResult::recovery`を、新しい保存領域と文書回復用コンストラクターへ渡す。
5. 送信スレッドで文書の`poll()`を進め、復元済みのレイヤーと編集セッションを採用する。

ファイル操作はGPUを呼び出さず、文書の終了とGPU喪失の後も固定値を利用できる。
CPU値の参照は不変として扱い、ファイル操作と作業スレッドの寿命を利用側が所有する。
書込みは`QSaveFile`で完了後に置換する。入力・予算・I/Oの失敗では元のファイルを保持する。
読込の失敗は`ReadResult::recovery`を空にして返す。

`Error`は成功、I/O失敗、不正なデータ、未対応の形式バージョン、予算超過を区別する。
引数`maximumBytes`は、ヘッダーを除くファイル内容、復号時の論理割当量と
文書のCPU回復値の上限に適用する。件数と長さは割当前に検査する。
書込み側も同じ読込予算を事前に確認し、成功したファイルを同じ上限で再読込できる。
CPU割当の管理量と、プロセス全体の物理メモリー使用量は別の指標である。

## バージョン1の形式

整数はビッグエンディアン、描画座標と寸法はIEEE 754の64ビット値を使う。
文字列は32ビットのUTF-16単位数と16ビットの各単位を保存し、QStringの内容を保持する。
可変バイト列は64ビットの長さ、件数と参照番号は32ビットで表す。
任意参照の空値は`0xffffffff`、真偽値は8ビットの0または1である。

| ヘッダー項目 | バイト数 | 内容 |
| --- | ---: | --- |
| 識別子 | 8 | `LPGPUREC` |
| 形式バージョン | 4 | 1 |
| 内容の長さ | 8 | ヘッダーを除くバイト数 |
| 内容のSHA-256 | 32 | 内容の破損検査 |

内容は次の順序で保存する。各表は件数と値の列から成る。

1. 選択マスクの入力表：ブラシ印列と切り詰め領域。
2. 質感表：幅・高さ、整数原点とアルファ列。
3. ラスター回復値表：チェックポイント、疎なタイル、確定入力列、履歴位置、作業中入力と確定要求。
4. レイヤー記録表：識別子、名前、不透明度、合成方式、画素とマスクの回復値への参照。
5. 文書履歴：各状態の下から上へのレイヤー記録参照列。
6. 現在の履歴位置、次の識別子、任意の未確定編集。

未確定編集は、確定前のレイヤー記録、対象、セッション回復値と文書採用待ちの有無を持つ。
通常合成と消去は0と1、画素とマスクの対象は0と1で表す。
共有する選択・質感・画素・マスク・レイヤー記録は表へ一度保存し、読込後も同じ参照を使う。
参照番号、チェックポイント、入力値と文書履歴は、画像側のCPU検査を通してから採用する。
画像側の描画発行とCPU回復値は、`KisGpuPaintInputValidation_p.h`の入力規則を共有する。

形式バージョンは入力列の描画規則も含む。描画規則や保存内容を変更するときは、対応する
形式の移行と固定画像の互換検査を定義する。

## 検証と保守

`libs/document/files/gpu/tests/KisGpuDocumentRecoveryFileTest.cpp`は、固定形式の読込、
背景保存中の文書変更、画素・マスクの編集中・確定待ち・採用待ち、共有履歴、
破損・巨大な件数・長さ、CPU予算と失敗時の元ファイル保持を検査する。
GPUでの再作成後に、保存した版の画素と未確定編集、Redo位置を照合する。

`tests/data/gpu_recovery_v1.bin`は、同じテストの明示的な値から作成したバージョン1の
維持対象である。入力値、採用範囲と生成元は隣のREADMEに記載する。
新しい形式バージョンを追加するときも、既存の固定ファイルと画像の検査を保持する。
