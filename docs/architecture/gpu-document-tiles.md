# GPU文書タイルと版の契約

## 目的と構成

`libs/image/gpu`はGPU上の疎な画素タイル、変更前後の版、操作ごとの完了状態、
バッファーのメモリー予算を所有する。`kritaimagegpudocument`はQt Coreと
wgpu-native 27.0.4.0を直接利用する。画像モデル、ブラシ、履歴、表示の利用側は、
この所有者へ描画命令を渡し、必要な版を保持する。

| ファイル | 所有内容 |
| --- | --- |
| `libs/image/gpu/KisGpuTileStore.h` | 版、単色描画、画素合成、明示的な転送、操作完了、予算と統計の内部API |
| `libs/image/gpu/KisGpuTileStore.cpp` | GPUバッファーの寿命、タイル共有、GPU内複製、計算命令と完了観測 |
| `libs/image/gpu/KisGpuTileComposite.cpp` | 画像版と選択マスクを読むGPU内合成 |
| `libs/image/gpu/KisGpuProjection.cpp` | レイヤー列から変更領域だけを一回で合成する投影生成 |
| `libs/image/gpu/KisGpuTileTransfer.cpp` | 保存用の非同期読取り、マッピングと画素の取込み |
| `libs/image/gpu/KisGpuTileStore_p.h` | 所有者内部の割当、版、完了と発行中資源の表現 |
| `libs/image/gpu/KisGpuTilePaint.wgsl` | GPU上の画素演算。Qtリソースとしてライブラリーへ組み込む |
| `libs/image/gpu/KisGpuEditSession.*` | 作業版の追加・差し替え、非同期確定、取消しと有限の履歴 |
| `libs/image/gpu/tests/KisGpuTileStoreTest.cpp` | 実GPUによる画素、版、予算、資源解放の契約 |
| `libs/image/gpu/tests/KisGpuTestDevice.*` | 試験と計測が所有する実GPUと明示的なCPU読み戻し |
| `libs/image/gpu/tests/KisGpuPaintBenchmark.cpp` | 固定入力による逐次発行と一括発行の実測 |
| `scripts/configure-gpu-document` | 固定Nix依存の取得とネイティブ構築の設定 |

`LIBREPAINT_BUILD_GPU_DOCUMENT=ON`でこの構築単位と試験を有効にする。
製品接続の受入れ前に資源契約を独立して検証するため、標準のアプリケーション経路との
接続は実装対象から分ける。ブラシ合成は[ラスター編集の比較契約](raster-edit-contract.md)を
入力とし、その画素規則を満たす実行処理を接続する。

## 画素と版

タイルは64×64画素、RGBA各8ビットの整数である。RGB値はアルファと独立して保持し、
GPUへ渡す単色値はRを整数の下位バイトに置く。アルファ0のRGB値も保存する。
タイル座標は符号付きで、画素座標を64で割った切り下げ値を使用する。
未配置のタイルは透明な黒として扱う。

`emptyVersion()`はタイルを持たない版を作る。`fill()`は長方形の内部を指定した単色へ
上書きし、新しい版を返す。対象外のタイルを元の版と共有し、変更したタイルに新しい
GPU領域を割り当てる。部分上書きでは元のタイルをGPU内で複製してから描画し、
全面上書きでは指定した色を直接生成する。CPUからの入力は座標と色の命令である。

`paint()`は単色の通常合成または消去を実行する。不透明度と選択範囲の一定被覆率を
8ビット値で渡す。選択境界は呼出し側が描画領域へ反映する。通常合成はアルファと
独立したRGB値を合成し、消去はRGB値を維持してアルファを減らす。透明な入力、
不透明度0、被覆率0は元の版と完了状態を返す。

複数の`PaintCommand`を渡す`paint()`は入力順に合成し、一つの版と完了状態を返す。
各タイルを一度だけ確保・複製し、そのタイルへ作用する命令をGPU上で順に実行する。
最大64タイル（1MiB）を一つのバッファーへ連続配置し、一回の計算発行で更新する。
デバイスのバッファーと計算発行の上限が小さい場合は、その上限で分割する。
この上限は、割当・発行の費用を減らしながら、共有による不要領域の保持量を抑える。
対象タイルと命令用バッファーの必要量を発行前に検査し、全命令を一回で発行する。
長いストロークの分割と発行時期は利用側が所有する。

`paintDabs()`は円・楕円の形状生成と通常合成・消去を一つのGPU処理で実行する。
中心、縦横の直径、縦横のフェード、色、不透明度、一定の選択被覆率、描画範囲を受け取る。
利用側は筆圧などを直径へ反映し、間隔に従って並べたブラシ印を入力順で渡す。
一つの印は描画領域・合成の32バイトと形状の32バイトを各対象タイルへ渡し、
GPUが画素位置から被覆率を計算する。長方形命令は32バイトの表現を維持する。

形状規則は既存の標準円マスク（突起数2、回転0、輪郭の追加標本化なし、
柔らかさ1、密度1、乱数変化0）である。
`brush_mask_contract.json`を既存の`KisCircleMaskGenerator`で検証し、
GPUの単精度計算は各成分1/255以内の差で受け入れる。
直径とフェードは有限の正数、フェードは1以下とする。
入力がこの範囲を外れる場合は`InvalidCommand`として全命令を発行前に拒否する。
追加の形状、回転、輪郭の追加標本化、質感は、それぞれの比較契約を追加して受け入れる。

`composite()`は別の版を入力として、同じキャンバス座標の画素を通常合成または消去する。
入力のGPUバッファーを直接読み、CPUへの画素転送を伴わず新しい版へ描画する。
入力元と描画先の割当が共通するタイルをまとめて計算発行する。
対象領域に入力タイルが存在する部分を更新し、未配置の入力は透明として元の版を共有する。
入力版と描画先の版は不変であり、操作完了まで両方を保持する。
個別画像の合成はこの操作を利用する。レイヤー列の投影には`project()`を利用する。

`compositeMasked()`は同じ座標のGPUマスクのアルファを画素ごとの被覆率として使用する。
マスクのRGB値は合成へ影響せず、未配置のマスクタイルは被覆率0として扱う。
入力、マスク、描画先を操作完了まで保持し、通常合成と消去を同じ画素規則で実行する。

`project()`は既存の投影版、下から順に並ぶレイヤー列、変更矩形を受け取る。
レイヤーには画素版、任意の選択マスク版、不透明度、合成方式を指定する。
変更矩形を透明へ戻し、各レイヤーを順番に合成して、一回の発行で一つの投影版を作る。
変更タイルを一度だけ確保し、部分変更では旧タイルを一度だけ複製する。
変更矩形の外は旧版と共有し、削除したレイヤーの旧占有領域は透明へ戻す。
旧投影と表示レイヤーのタイルから対象を求め、疎な画像の空白領域は割り当てない。
必要量は全レイヤーを含めて発行前に検査し、拒否時は旧投影を維持する。
入力版とマスクは完了まで保持する。変更矩形の決定は画像モデルが所有する。

CPUとGPUは`libs/image/tests/data/raster_edit_contract.json`を共用する。
固定された13入力を、一画素、負座標、タイル境界をまたぐ3領域で実行し、
単色入力、GPU画素入力、GPUマスクを使う入力で、描画領域外を含めた全成分の完全一致を要求する。
画素ごとに濃さが異なるマスク、疎な選択範囲、RGB値からの独立性も検査する。
色変換は、その入力形式と画像契約を追加して受け入れる。

版は不変の値である。未確定の版を捨てると取消しになり、保持した前後の版は
Undo／Redoの復元先として利用できる。履歴項目の登録と採用判断は利用側が所有する。
タイル対応表はCPUで保持し、変更時に複製する。画素の正本はGPUバッファーが所有する。

## 作業版と履歴

`KisGpuEditSession`は一つのラスター描画先に対する作業版と履歴を所有する。
タイル所有者を借用し、その発行スレッドで利用する。
初期版を指定すると、取込み済みの画像を最初の確定版として編集を始める。
初期版は同じタイル所有者に属し、完了済みであることを要求する。
未完了・別の所有者の版は`std::invalid_argument`として構築を拒否する。
`begin()`は確定済みの版を起点として操作識別子を返す。
識別子はセッションの寿命と操作番号を含み、取消し済みの操作、別文書、閉じた文書からの
入力を`Stale`として拒否する。識別子の保持はGPU資源の寿命へ影響しない。

`append()`は直前の作業版へブラシ印を追加し、`replace()`は確定済みの起点から
全ブラシ印を描き直す。図形編集の利用側は後者で前の形状の占有領域を取り除く。
`poll()`は最新の処理の成功後に表示用の作業版を採用する。
確定要求後は同じ版の処理完了を待ち、画素を再描画せず履歴へ登録する。
GPUが処理を拒否した場合は直前の作業版を維持する。
非同期処理の失敗は`Failed`として確定を止め、確定済みの版を表示する。

取消しは作業版の参照を解放し、保持済みのRedo先を維持する。
Undo／Redoは確定済みの版を選び直す。新しい編集の確定はRedo先を置き換え、
空の編集の確定は履歴を維持する。履歴は構築時に指定した編集数と現在の版を保持する。
上限を超えた古い版の解放と`clearHistory()`で、参照のなくなったGPU割当を解放する。
作業版・履歴の切替は画素のCPU読取りとアップロードを伴わない。

## 明示的なCPU読取り

`readback()`は保存や外部の画素利用者のために、指定した版の矩形を非同期で読み取る。
発行時点の版を固定し、先行する描画完了を同じGPUキュー上で待ってから読み取る。
後続の編集は別の版へ進められる。未配置の画素は透明な黒として返す。
結果は行間の余白を持たないRGBA8のバイト列で、完了が`Succeeded`になった後に
`Readback::bytes()`から取得する。

読取り用GPU領域は文書の予算へ計上する。指定領域が予算、デバイス上限、
CPU結果の上限（2GiB未満）を超える場合は`BudgetExceeded`として発行前に拒否する。
大きな文書の保存は利用側が読取り領域を分割する。CPU結果は呼出し側へ共有して渡し、
GPUの版と一時領域は完了後の`poll()`で解放する。CPU結果は文書所有者の破棄後も利用できる。

## 明示的な画素の取込み

`upload()`は再読込や回復に使うRGBA8のバイト列を、指定した矩形へ取り込む。
行間の余白を持たないバイト列を要求し、CPU入力は呼出しから戻った後に解放・変更できる。
変更タイルを新しいGPU領域へ置き、矩形の外部と変更前の版を保持する。
部分変更では元のタイルを一度複製し、全面変更では複製を省く。
タイルと転送用領域を予算へ計上し、入力サイズ、予算、発行上限を発行前に検査する。
完了した読取り結果は元のデバイスの破棄後も保持でき、別デバイスへ取り込んで編集を再開できる。
保存形式への接続と未保存の編集の自動回復は、利用側の保存・回復契約を加えて受け入れる。

## 操作順序と寿命

利用側が作ったデバイスを`KisGpuTileStore`へ渡す。所有者はデバイスの参照を取得し、
同じキューへ操作を入力順に発行する。次の操作は、先の操作の版を完了待ち前に参照できる。
操作には発行順の番号と`Pending`、`Succeeded`、`Failed`の完了状態がある。
キュー上の完了とGPU検査・メモリー不足の検査結果を合わせて操作の成功を判断する。
利用側は`Succeeded`を確認して結果を採用する。

`poll()`は待機せず完了を観測し、完了した操作が保持する資源を解放する。
GPUからの通知は完了値を記録する。発行側は全通知と入力版の成功を確認して結果を公開し、
資源を解放する。
所有者のAPI呼出しと`poll()`は、デバイスへ命令を発行する同じスレッドから実行する。
所有者の構築時に、完了回収前の発行数の上限を指定する（初期値256）。
上限に達した描画・合成・読取りは`QueueFull`として資源確保と発行の前に拒否する。
利用側は入力順を保持し、`poll()`で完了を回収してから拒否された操作を再試行する。
発行を伴わない空の操作は上限に達していても元の完了状態を返す。
`Version::tile()`はバッファーとその内部位置を返す。利用側は、その位置から
`TileBytes`の範囲を読み、読取り完了まで対象の版を保持する。
空のバッファーは未配置のタイルを表す。

所有者の破棄時は最後に発行した操作の完了を待つ。版が所有者より長く生きる場合は、
版がタイルとデバイスの参照を保持する。

デバイス所有者は喪失時に`invalidateDevice()`を通知する。通知は所有者の生存中に
任意のスレッドから行え、明示的なネイティブデバイスの破棄は発行スレッドで通知後に行う。
通知はCPUへのマッピングと同期し、破棄後のバッファーから画素を取得することを防ぐ。
以後の描画・合成・読取りは`DeviceLost`として発行前に拒否する。
未完了の操作は直ちに`Failed`を返し、後続の通知でも成功へ戻らない。
操作が保持する資源は、マッピングを含む全通知が届いた後に回収する。
完了済みのCPU読取り結果は成功状態と画素を保持する。
GPU喪失後の文書回復と再作成は、保存・回復の契約を加えて受け入れる。

## 予算と失敗

予算には、この所有者が確保した全タイルバッファーと操作用の一時バッファーを含める。
履歴・作業版の参照と未完了の操作が資源を保持している間も計上する。
複数タイルが共有する割当は、最後のタイルの参照が解放されるまで全体を計上する。
割当内の一部を置き換えた場合も、保持されている領域を含めた予算で次の編集を検査する。
対応表と読取り結果のCPUメモリー、GPUドライバーの内部領域は
それぞれの所有者が計測する。`residentBytes`はこの範囲の確保済みバイト数を返す。

予算またはデバイスのバッファー上限の超過は`BudgetExceeded`、別の所有者の版や未初期化の版は`InvalidVersion`を返す。
これらの拒否では画素、確保済みバッファー、キューと転送統計を維持する。
空の領域は元の版とその完了状態を返し、GPUへの発行を伴わない。
GPU検査で失敗した操作は`Failed`として採用を止める。

`commandUploadBytes`は命令バッファーの転送量、`tileCopyBytes`はGPU内のタイル複製量、
`submissions`は操作の発行数、`computeDispatches`は計算発行数、
`pixelReadbackBytes`は明示的なCPU読取り量、`pixelUploadBytes`は明示的な取込み量を累積する。予算と画像結果の検査を維持し、
タイルの確保方式や命令のまとめ方を変更する。

## 利用方法と保守

構築と実行のコマンドは開発マニュアルの
[GPU文書タイルの検証](DEVELOPMENT.md#gpu文書タイルの検証)を参照する。
試験はMetalまたはVulkanの実GPUを必要とする。
固定入力で負座標、タイル境界、部分・全面上書き、版の独立性、取消しと保持済みのRedo先、
予算超過、未完了資源、所有者の破棄、連続編集時の解放を検査する。
一括描画は逐次描画との画素一致、タイルごと一回の複製、一回の発行、
命令も含めた予算と一括拒否を検査する。
タイルの連続配置はバッファー内部位置からの読取り・複製、デバイス上限による分割、
共有された割当の全量計上と最後の参照の解放を検査する。
版どうしの合成は多色の入力、範囲の切り詰め、レイヤー順序、半透明レイヤーの固定画素、
予算拒否、未配置の入力、入力版の解放と非同期完了を検査する。
投影は一回の発行、部分変更の一回複製、レイヤー削除、空のレイヤー列、
マスクと不透明度、疎な広域画像とデバイス上限による分割を検査する。
検証用のCPU読み戻しは試験側の資源で実行する。
製品用の明示的読取りは、未完了の版の固定、後続編集との独立性、疎な画素と負座標、
拒否の原子性、GPU領域の解放、所有者破棄後のCPU結果を検査する。
画素の取込みはCPU入力の解放、透明画素のRGB、旧版の独立性、拒否の原子性、
新しいデバイスへの復元と編集・Undoの再開を検査する。
デバイス喪失は未完了の描画・依存する操作・読取りの失敗、確定の抑止、
明示的なデバイス破棄後の通知と資源回収を検査する。

逐次発行と一括発行の比較は開発マニュアルの
[GPU描画の一括発行計測](DEVELOPMENT.md#gpu描画の一括発行計測)を参照する。
