# KRAからGPU文書への復元

## 目的と構成

`plugins/impex/libkra/gpu/KisGpuKraLoadJob.*`は、既存KRAパーサーが取得したラスター画素を
GPU文書へ復元する。`kritagpukraload`が既存の文書処理と具体的なGPU画像所有者へ依存する。
GPU画像側はKRAと文書UIから独立している。

対象はRGBA8のsRGB画像、レイヤー順序・名前・不透明度・表示状態・描画ロック、通常・消去合成と、
既定値が0のアルファ8ビット透明度マスクである。CPU描画デバイスの配置済み領域から
64×64の疎なRGBA8チェックポイントを作成する。CPUデバイスの整数オフセット、
負の座標、GPUタイルをまたぐ配置と透明画素のRGBを保持する。
マスクはアルファを復元し、RGBを0とする。マスク演算はアルファを利用する。

文書寸法、名前、解像度、文書情報と補助設定の固定値は`KisGpuKraMetadata.h`が定義し、保存側と共有する。
`documentInfoXml`に題名、説明、ライセンス、作者と連絡先を既存の文書情報形式で保持する。
取得時は日付・編集回数と作者を変更せず、読込操作と解析用文書の終了後も値を利用できる。
`documentSettingsXml`は格子、補助線と対称軸を保持する。既存パーサーが設定から再作成する
補助ノードは画素レイヤーと区別する。製品の読込入口は文書所有者へ同じ固定値を引き渡し、
保存時に既存KRAの設定へ復元する。補助設定の画面表示・編集は専用UIの対象範囲として扱う。
高ビット深度や別プロファイルの暗黙変換は精度を失うため、対象外の画像として拒否する。

## 利用方法と寿命

1. GUI兼GPU送信スレッドで、登録済みの未使用の空文書、KRAのパスとCPU読込予算を渡す。
   文書所有者が保存領域、保持する編集数、回復予算とGPU寿命を管理する。
2. 同じスレッドから`poll()`を進める。初回の`Reading`は既存の同期パーサーと
   CPUチェックポイント抽出を実行するため、ファイルの読込・解析時間を要する。
3. `Restoring`では既存の文書回復を非同期に進める。Qtのイベント処理も継続する。
4. `Succeeded`となった後に、同じ文書モデルのレイヤー列と`metadata()`から完成値を受け取る。

CPUチェックポイント完成後、GPU復元を始める前に解析用の文書とCPU画像を解放する。
文書の`restoreInitial()`がCPU値を検査し、同じモデル上でGPU復元を開始する。
GPU文書は新しいレイヤー識別子列と一状態の履歴で始まり、保存時の描画命令を再実行しない。
完成後の通常描画と保持済みUndoは既存GPU版を利用する。

登録済み文書の識別子・共有参照・保存領域を維持し、画素の再転送を伴う所有権の移し替えを省く。
途中のレイヤー列と文書属性は全復元の成功後に公開する。
休止中は復元を待ち、文書所有者によるGPU再作成後に同じ読込操作を継続する。
操作の破棄は読込操作自身のCPU値と参照を解放する。利用側は読込の取消し・失敗時に
未公開の文書を共有文書所有者から閉じる。完成した文書は読込操作の終了後も編集できる。

## 予算・対象の検査と失敗

チェックポイントのタイル、座標、名前とレイヤー記録はCPU回復予算へ加算し、
各割当前に検査する。固定した文書情報と補助設定のバイト数も同じ予算へ加算し、GPU復元前に検査する。
GPU復元前に画像側の`validRecovery()`も検査する。
文書自身の回復予算と履歴上限も`restoreInitial()`で検査する。既存の編集を持つ文書は
入力不正として拒否し、現在の画素と履歴を維持する。
既存パーサーによる展開、文書情報のDOM解析・直列化、CPU画像と投影の割当は既存文書処理の所有量となる。
回復値の論理容量とプロセス全体の物理使用量は区別する。

画像契約で表現できるレイヤー属性と画素形式を検査してからGPUへ発行する。
非表示レイヤーも画素を復元して保存し、GPU投影は表示中の層だけを使用する。
描画ロックは画素・マスク入力に適用し、表示とロックの解除後に同じGPU版から編集できる。
グループ、カラーラベル・チャンネル制限・アニメーション・レイヤー効果、
通常・消去以外の合成、既定値が0以外の画素・マスク、ベクターマスク、
非表示・ロック中のマスク、文書の選択範囲と不透明な背景は、内容の欠落を避けるため拒否する。
描画補助ツールの値はこの固定値の対象に含まれず、再保存で失われるため
`UnsupportedDocument`としてGPU発行前に拒否する。
これらの対象を拡大する場合は、対応するGPU文書の状態と画像・編集契約を先に定義する。

`Error`は入力の不正、KRA解析失敗、未対応の文書、CPU予算不足とGPU拒否を区別する。
`gpuError()`が復元時の予算超過やデバイス喪失を返す。失敗時は完成文書を公開せず、
元のKRAファイルを維持する。復元失敗後の再読込は新しい空文書と読込操作で行う。

## 検証と保守

`plugins/impex/libkra/gpu/tests/KisGpuKraLoadJobTest.cpp`は、GPU終了後のKRA再読込、
画素・マスクを含むGPU投影の完全一致、復元後の描画・Undoと新しい識別子を検査する。
負の座標、整数オフセット、タイル境界、透明RGBと空文書も照合する。
固定した文書情報を再保存へ渡し、元の文書・読込操作の終了後も題名、説明、ライセンス、
作者と連絡先が保持され、取得だけでは保存回数が増えないことを検査する。
対象外の文書とCPU予算はGPU発行前に拒否し、GPU予算不足と喪失では途中の文書を
公開せず、別のGPUへ再読込できることを検査する。
格子、補助線と対称軸を個別・同時に持つKRAをGPU文書経由で再保存し、
既存KRAパーサーで設定の完全一致を確認する。固定値の予算不足はGPU発行前に拒否する。
登録済み文書への読込は、復元開始後のGPU休止・再開、同じ文書参照、チェックポイントの
一回の転送と、既存文書の上書き拒否を検査する。
