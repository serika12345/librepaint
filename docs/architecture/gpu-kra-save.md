# GPU文書のKRA保存

## 目的と構成

`plugins/impex/libkra/gpu/KisGpuKraSaveJob.*`は、確定済みGPUレイヤー列を固定し、
既存のKRA保存処理へ渡す。`LIBREPAINT_BUILD_GPU_DOCUMENT`が有効な構成で、
`kritagpukrasave`が画像側の固定版読取りと既存の文書処理へ依存する。
画像側のGPUタイル所有者は、文書UIとファイル形式から独立している。

保存対象はRGBA8のsRGB画素、下から上へのレイヤー順序、名前、不透明度、通常・消去合成と
任意の透明度マスクである。固定版読取りで取得したRGBA8を既存のCPU描画デバイスへ移し、
KRAライターが色プロファイル、文書寸法、解像度とともに保存する。マスクはKRAの
アルファ8ビット選択として保存する。描画時のマスク演算もアルファだけを利用する。

## 利用方法と寿命

1. GUI兼GPU送信スレッドで、保存領域、`layers()`、次のレイヤー識別子を取得する。
2. 文書寸法、名前、解像度、保存先と読取り用CPU予算をコンストラクターへ渡す。
   解像度は既存画像と同じ画素/ポイントで、1が72dpiに相当する。
3. 同じスレッドで`poll()`を進め、Qtのイベント処理も継続する。
4. `Succeeded`を受けて保存成功を採用する。失敗は`Failed`と`error()`で判定する。

`Reading`は版を固定した疎なタイル読取りを行う。完成したCPU値を取得するとGPUへの参照を
解放し、保存用の独立した文書を構築する。`Preparing`では既存画像の初回投影を待ち、
`Writing`では既存文書の背景保存とその完了通知を利用する。
KRAのプレビューと統合画像の生成には既存のCPU投影を使う。

元のGPU文書は保存と並行して編集・終了できる。読取り完了後はGPUの終了も保存に影響しない。
読取り途中で操作を破棄すると公開を取り消す。背景書込み開始後の破棄は既存文書の
完了待ちを利用して保存用文書の寿命を保つ。呼出しと破棄はGUI兼GPU送信スレッドで行う。

## 検査と失敗

文書寸法、有限かつ正の解像度、保存先、XMLで表現できる文書名・レイヤー名を
GPU読取り前に検査する。サロゲート対を持つUnicode文字も保持する。
読取り用CPU予算は固定版読取りの論理容量に適用する。既存の保存用画像、投影、
背景保存用複製と圧縮処理のメモリーは、それぞれ既存の文書処理が所有する。

`InvalidInput`は保存情報の不正、`ReadbackFailed`はGPU読取りの失敗、`SaveFailed`は
色プロファイルやKRA保存の失敗を表す。`readbackError()`がCPU/GPU予算とGPU喪失などの
読取り原因を区別し、`errorMessage()`が診断を返す。読取り失敗時は保存先を変更しない。
背景保存のファイル置換とエラー処理、キャンバス外画素の切り詰め設定は既存KRA経路が所有する。

## 検証と保守

`plugins/impex/libkra/gpu/tests/KisGpuKraSaveJobTest.cpp`は、保存中の文書変更・終了、
GPU終了後の保存完了と既存KRAパーサーによる再読込を検査する。画素、マスクのアルファ、
レイヤー属性、寸法、解像度とICCデータを照合する。CPU予算、GPU喪失、不正な名前、
保存先の失敗と背景書込み中の破棄も検査する。

保存対象の拡大は、形式が持つ責務と画像側の契約を合わせて定義する。
GPU投影とKRAの統合画像の対応は、製品統合時の画像契約で検証する。
