# GPUレイヤー文書と編集履歴

## 目的と構成

`libs/image/gpu/KisGpuLayerDocument.*`は、レイヤー列、画素とマスクの版、名前、
不透明度、合成方式、表示状態、描画ロックと、文書全体で一つのUndo/Redo履歴を所有する。
描画とレイヤーの追加・削除・並べ替え・属性変更を同じ操作順で扱う。
`KisGpuEditSession`が一回のラスター編集と回復値を、`KisGpuLayerDocument`が
レイヤーへの採用と文書履歴を所有する。構築単位は`kritaimagegpudocument`で、
依存先はQt Coreと固定版wgpu-nativeである。

文書は具体的な`KisGpuTileStore`を共有所有する。返した編集セッションも保存領域を
保持し、文書の終了後に届いた入力を安全に拒否できる。呼出しと破棄は保存領域の
送信スレッドで行う。利用側は`KisGpuBrushStroke`が借用するセッションを、
ブラシ入力生成器より長く保持する。

## レイヤーと履歴

レイヤー識別子は文書内で単調に増加し、Undoと新しい分岐でも再利用しない。
列は下から上の順に並ぶ。各履歴状態は、GPU資源から独立したレイヤー記録と画素・マスクのCPU回復値を保持する。
文書単位の保持表は、CPU回復値の参照に対応するGPU版を所有する。
表示と編集は、現在のレイヤー記録と保持表から同じGPU版を取得する。
変更していないレイヤー記録と回復値を履歴間で共有する。

履歴の上限は生成時に指定し、現在の状態と指定回数の取消し先を保持する。
上限を越えた状態と、新しい操作で置き換えたRedo先を解放する。
その状態だけが利用するGPU版は保持表からも除く。
Undo/Redoは保持済みのGPU版を即時に採用する。この場合、GPUの再描画と画素転送を伴わない。
同じ名前・層順・属性を指定した場合は履歴を追加しない。

`setLayerVisible()`と`setLayerLocked()`は表示状態と描画ロックを同じ文書履歴へ記録する。
画素・マスクの版を共有し、変更自体のGPU発行と画素転送は0である。
`layers()`は非表示レイヤーも含めた全記録を返し、`projectionLayers()`は表示中の層だけを返す。
非表示またはロック中の層への`begin()`は、画素・マスクとも`LayerNotEditable`を返す。
描画中の属性変更は`Busy`を返し、受理済みの入力と作業版を維持する。
CPU回復値、固定版読取り、GPUの一時解放・再開は両属性を保持する。

`KisGpuLayerDocumentResidency.cpp`はGPU履歴の保持と退避済み状態への移動を所有する。
`evictHistory()`は、現在のレイヤーとマスク以外のGPU版を保持表から解放し、CPU履歴と
回復値を維持する。編集・復元中は`Busy`を返す。利用側が保持した旧版は、その参照が
解放されるまでGPU予算へ含める。退避自体のGPU発行と画素転送は0である。

退避した版へのUndo/Redoは要求の受付を返し、`Restoring`へ移る。利用側は`poll()`を
進め、`Idle`になった後に移動先を利用する。復元対象は指定した履歴状態だけで、既に
保持する画素とマスクは再利用する。復元中の表示は直前の状態を保ち、完成後にレイヤー列と
履歴位置を一緒に採用する。`recovery()`は受付済みの移動先を保持し、GPU喪失後にも
その要求を再開できる。復元の失敗時も直前の表示とCPU履歴を維持する。
`cancelHistoryRestore()`は履歴移動の復元要求と途中の結果を解放し、直前の履歴位置へ戻す。

## GPU資源の一時解放と再開

`suspend()`はCPU回復値を固定して`Suspended`へ移り、文書が所有するGPU版、
編集セッションと保存領域への参照を解放する。CPU履歴、位置、識別子と受付済みの
編集中・確定待ち・採用待ちの入力を維持する。画素読取りとGPUへの追加発行を伴わない。
履歴復元中は受付済みの移動先を保持する。チェックポイント集約の候補は解放し、
集約状態を空値へ戻す。元のCPU回復値を維持するため、保守操作を後から再試行できる。

利用側は同じ送信スレッドで次の順序を実行する。

1. 入力と表示への新しい要求を保留し、対象文書の`suspend()`を呼ぶ。
2. 表示用画像、旧版と古い編集セッションなど、利用側が保持したGPU参照を解放する。
3. デバイスを終了する場合は、共有する各文書のCPU値を固定した後に所有者を終了する。
4. 利用可能な保存領域を`resume(store)`へ渡す。状態は`Restoring`となる。
5. `poll()`で復元を進め、完成したレイヤー列と必要に応じて新しい編集識別子を採用する。

一時解放中と初回の再作成中は、`layers()`と`projectionLayers()`が空列を返す。
履歴のCPU値と件数は保持し、編集・構造・履歴操作を保留する。
以前の入力識別子は一時解放時に無効となり、再開後にも拒否する。
すでに一時解放した文書への`suspend()`は成功する。

`resume()`は実行中に`Busy`、空の保存領域に`InvalidInput`、利用不能なデバイスに
`GpuRejected`を返し、一時解放済みのCPU値を維持する。CPU予算の検査で`suspend()`を
拒否した場合も元の状態を維持する。復元失敗では`suspend()`でCPU値を保持した状態へ戻し、
容量を確保した保存領域へ再開できる。GPU喪失後の文書も同じ手順を使う。
OS通知、入力・表示の停止と共有デバイスの寿命は、利用側のライフサイクル所有者が扱う。

## 回復命令のチェックポイント集約

`KisGpuLayerDocumentCompaction.cpp`は、現在の画素またはマスクの回復命令を、配置済み
タイルのCPUチェックポイントへまとめる。読取りとチェックポイント生成は、既存の
`KisGpuEditSession`と`KisGpuRecoveryCompaction.cpp`の非同期処理を利用する。

利用側は`compactRecovery(id, target)`を明示的な保守操作として呼び、`poll()`を進める。
処理中の状態は`Compacting`で、表示とCPU回復値は元の状態を保つ。編集開始、構造変更、
履歴移動と退避は`Busy`、`clearHistory()`は`false`を返す。存在する画素・マスクが対象であり、
対象のないマスクは`InvalidInput`を返す。既に命令が空の対象は直ちに成功する。

`recoveryCompactionStatus()`は受付前の空値、`Pending`、`Succeeded`、`Failed`を返し、
失敗の原因は`recoveryCompactionError()`で取得する。読取りは一回の`poll()`につき
最大一タイルである。すべての読取りに成功した後、同じ回復値を参照する各履歴記録を、
一つの不変チェックポイントへ置き換える。GPU版、他の画素対象、履歴位置・順序・属性は維持する。
次の描画はチェックポイントを下地として命令を追加する。利用側が先に固定したCPU回復値も維持する。

CPU予算は元の履歴、処理中の回復値、チェックポイントと採用用の履歴記録を合わせて
発行前に検査する。`recoveryBytes()`は処理中の予約量も含む。GPU予算不足や読取り途中の
GPU喪失では候補を解放し、元のCPU値を維持する。容量を確保した後に再試行できる。
この操作は通常描画から独立した明示的な画素読取りである。

## 編集と表示の利用方法

1. `addLayer()`でレイヤーを作り、返した識別子を保持する。
2. `begin()`へ識別子と`Target::Pixels`または`Target::Mask`を渡す。
3. 返した`Editing::session`と`token`でブラシ入力を追加・差し替えする。
4. 文書の`poll()`で完了を回収し、`projectionLayers()`をレイヤー投影所有者へ渡す。
5. 文書の`commit(token)`または`cancel(token)`で操作を終える。

編集開始は、成功済みGPU版と対応するCPU回復値を編集セッションへ直接渡す。
履歴は文書が所有するため、このセッションの取消し履歴は0回とする。
開始時の画素転送と命令の再実行を伴わず、確定後に新しいレイヤー記録を文書履歴へ採用する。

`layers()`は確定済み状態、`projectionLayers()`は成功済みの作業版を反映した表示用の列を返す。
引数を`false`にすると確定済みの列を返す。マスクの初回編集では、
作業版が完成するまで元の表示を保持する。選択と質感は編集セッションの入力を利用する。
投影の完了と公開は[GPUレイヤー列と完成済み投影の管理](gpu-layer-projection.md)が所有する。

編集中はレイヤー構造の変更と文書のUndo/Redoを保留する。
取消しはRedo先を保持し、完了済みの確定はRedo先を新しい分岐へ置き換える。
`clearHistory()`は編集中の状態を保ちながら他の取消し先を解放し、成功を返す。
操作識別子はセッションに属し、取消し・確定・文書終了後と別文書からの入力を拒否する。

## 予算・失敗・回復値

文書のCPU予算は、保持履歴と編集中の回復値を対象とする。
共有するレイヤー記録と画素・マスクの回復値を一度だけ数え、新しい編集記録と履歴状態に必要な量を開始前に予約する。
編集セッションへ残りの上限を渡し、CPU入力の超過をGPU発行前に拒否する。
返した編集セッションを保持する利用側は、その参照の寿命を所有する。
GPU資源の予算は保存領域とデバイスが管理し、利用側が保持する版やセッションも含める。

GPU喪失と操作の失敗では、確定済みレイヤーと履歴を維持する。
文書の`recovery()`は、レイヤー構造、各画素・マスクのCPU回復値、全履歴と現在位置、
次の識別子、未確定編集を返す。記録はGPU資源と操作識別子から独立し、元の文書と
保存領域を解放した後も保持できる。共有するレイヤー記録と各画素・マスクの回復値は、履歴間で同じ参照を使う。
GPU版を履歴から選び直すときも、その版に対応する回復値を一緒に採用する。

## 文書全体の非同期回復

`KisGpuLayerDocumentRecovery.cpp`はCPU回復値の検査、再実行と文書への一括採用を所有する。
利用側は新しいGPUの保存領域、履歴上限、回復値とCPU予算を回復用コンストラクターへ渡し、
`poll()`を繰り返す。構造・履歴位置・チェックポイント・CPU予算の不正は、GPU発行前に
`std::invalid_argument`で返す。復元中の状態は`Restoring`であり、構造の変更と履歴操作を保留する。
`clearHistory()`は復元中に`false`を返す。

指定した履歴位置の画素とマスクを一度ずつ再作成し、全履歴のCPU記録を保持する。
他の履歴位置に必要なGPU版はUndo/Redoの要求時に復元する。名前や不透明度だけが異なる
記録は同じGPU版を共有し、画素割当を増やさない。未確定編集も完成した後に、レイヤー列と履歴を
一緒に公開する。復元中の`layers()`と`projectionLayers()`は空列を返す。
一回の`poll()`から発行するGPU操作は最大一回とし、発行枠の不足は次の回収後に再試行する。
途中のGPU予算超過や喪失は`Failed`となり、部分的なGPU結果を解放する。`recoveryError()`で発行拒否またはGPU喪失の原因を取得できる。
`recovery()`は元の要求を保ち、利用側は別の保存領域で同じ文書を再試行できる。

編集中の回復では、復元済みの確定版を再利用して未確定の入力だけを再実行する。
同じ画像を表す別のCPUチェックポイントを編集側が保持していても、下地の再アップロードを
伴わない。`currentEditing()`から新しいセッションと操作識別子を取得し、編集を再開できる。
元のセッションの操作識別子は新しい文書とセッションで拒否する。
確定要求済みの編集は完了後に一つの文書操作として採用し、Redo先を新しい分岐へ置き換える。
セッションだけが確定済みで文書への採用を待つ場合も、同じ操作順を維持する。
回復値の利用側は返したCPU値の寿命を所有する。この値の永続化とファイル形式は、
[GPU文書回復ファイル](gpu-document-recovery-file.md)が定める。
`validRecovery()`はGPU生成前に文書構造・入力値・CPU予算を検査し、ファイル操作からも利用できる。

## 検証と保守

`libs/image/gpu/tests/KisGpuLayerDocumentTest.cpp`は、複数レイヤーへの描画と構造操作の
Undo/Redo、マスク、プレビュー、取消しと分岐、CPU予算、GPU旧版の解放、
文書終了後の入力と保存領域の寿命を検査する。Undo後の各レイヤーとマスクは、
保持した回復値を新しいGPUで再実行し、元の版との画像完全一致を検査する。

`libs/image/gpu/tests/KisGpuLayerDocumentRecoveryTest.cpp`は、文書全体の構造・履歴、
画素とマスクの編集中・確定待ち・採用待ちの復元を画像完全一致で検査する。
CPU値の不正、部分復元中の予算超過・GPU喪失、資源解放と再試行も対象とする。

`libs/image/gpu/tests/KisGpuLayerDocumentResidencyTest.cpp`は、GPU過去版の解放と
利用側が保持する旧版の寿命、画素・マスクの遅延Undo/Redo、現在位置だけの回復、
復元中の表示維持、予算超過・取消し・GPU交換後の再試行を検査する。

`libs/image/gpu/tests/KisGpuLayerDocumentCompactionTest.cpp`は、画素・マスクの
疎なチェックポイント、GPU版・履歴・固定済みCPU値の維持、新しい編集の継続と別GPUへの
回復、CPU発行前検査、GPU予算不足・部分読取り中の喪失を検査する。

`libs/image/gpu/tests/KisGpuLayerDocumentSuspendTest.cpp`は、同じ文書の一時解放と
GPU交換後の再開、画素・マスクの未確定入力、古い識別子の拒否、履歴・Redo・属性の維持、
移動先の復元途中と失敗後の再試行、保守操作の取消しとGPU喪失を検査する。

`libs/canvas/gpu/tests/KisGpuCanvasRendererTest.cpp`は、文書から作業版、確定、
Undo/Redo、別文書の投影とキャンバス描画までを連結し、通常操作の画素転送0を検査する。
文書履歴、編集セッションと投影の境界を変更するときは、関連契約を実GPUで実行する。
