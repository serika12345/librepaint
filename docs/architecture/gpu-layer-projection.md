# GPUレイヤー列と完成済み投影の管理

## 目的と構成

`libs/image/gpu/KisGpuLayerProjection.*`は、下から順に並ぶレイヤー入力と、
その入力から完成した投影画素を一緒に保持する。画像側がこの所有者を持ち、
表示側は成功済みの`Snapshot`から表示用画像を生成する。
`KisGpuTileStore::project()`がGPUの合成実行を、`KisGpuLayerProjection`が
変更領域の決定、要求の置換と結果の公開を所有する。

構築単位は`kritaimagegpudocument`であり、依存先はQt Coreと固定版wgpu-nativeである。
所有者はタイル保存領域を借用し、呼出しと完了回収を同じ送信スレッドで行う。
タイル保存領域の寿命はこの所有者より長くする。返したスナップショットは、
両所有者の終了後も入力画素と投影画素を保持できる。

## 入力と変更領域

生成時に固定したキャンバス矩形を指定する。空の矩形と整数で表現できない境界は
`std::invalid_argument`となる。`setLayers()`はレイヤーごとの不変の画素版、
任意のマスク、不透明度と合成方式を受け取る。

画素だけが変わる場合は、変更前後の版でGPUタイルの割当と位置を比較する。
共有しているタイルを維持し、変わったタイルのキャンバス内部分を再合成する。
層順、マスク、不透明度、合成方式の変更と削除では、対応する変更前後の層が占める
タイルを対象にする。不透明度0の層とキャンバス外のタイルは再合成領域へ含めない。
タイル位置の演算を64ビットで行い、キャンバスへ切り詰めてから変更矩形をまとめる。

変更領域の決定はGPUタイルの情報だけを読み、画素のCPU転送を伴わない。
複数の変更タイルを囲む矩形を`project()`へ渡し、その内部の配置済みタイルだけを処理する。
同じ入力を渡した場合は投影の版を共有し、追加のGPU発行を伴わない。

## 完了と利用方法

1. 編集セッションの`preview()`や`head()`を対象レイヤーの画素版へ設定する。
2. `setLayers()`へ列全体を渡す。未完了の入力もGPUキューの順序で受理する。
3. 所有者の`poll()`を呼び、`status()`で最新要求の完了を調べる。
4. 成功済みの`snapshot()`から投影版を取得し、`textureSnapshot()`とキャンバス描画へ渡す。

公開するレイヤー情報と投影画素は、最新の受理済み要求が成功した時点で一緒に切り替える。
後続要求があるときは、その前の要求だけが完了しても中間結果を公開しない。
キュー・予算超過や無効な版の拒否では、受理済み要求と公開済み結果を保持する。
GPU処理の失敗でも直前の公開済み結果を保持し、GPU喪失は上位の文書回復へ伝える。
別の文書は独立した所有者を持ち、同じGPUを共有する場合もレイヤー情報と投影を分離する。

## 検証と保守

`libs/image/gpu/tests/KisGpuLayerProjectionTest.cpp`は、層順、マスク、不透明度、消去、
削除、共有タイル、最新要求の採用、拒否後の再試行、GPU喪失、符号付き座標の両端と
所有者終了後の画素保持を検査する。画像は`project()`による全面再合成と完全一致させる。

`libs/canvas/gpu/tests/KisGpuCanvasRendererTest.cpp`は、編集プレビューの差し替え、
同じ版の確定、Undo/Redo、別文書の投影と、以前のフレームの保持を連結して検査する。
画像側の公開条件と表示側の画像保持を変更するときは、両契約を実GPUで実行する。
レイヤーの木構造、グループ合成、文書全体の履歴と回復は、それぞれの画像・文書操作の
契約を伴う統合単位で扱う。
