# GPU描画ツールの入力待ち列と寿命

## 目的と構成

`libs/tools/gpu/KisGpuStrokeInput.*`は、一つのツール操作について、正規化した入力の待ち列、
形状の差し替え、確定待ち、取消しとGPU交換後の継続を所有する。
具体的なブラシ生成器へ依存し、その先の画像所有者が画素・編集版と文書履歴を管理する。
ツール側の待ち列はCPU値であり、GPUへの画素転送を伴わない。

| 所有先 | 保持する状態 |
| --- | --- |
| `libs/tools/gpu/KisGpuStrokeInput.*` | 文書のCPU操作識別子、固定した設定と資源値、未処理の入力、公開待ちの差し替えの全入力、確定要求。 |
| `libs/painting/gpu/KisGpuBrushStroke.*` | 受理した印までの位置・筆圧・間隔・採色位置と、一要求の命令生成。 |
| `libs/image/gpu/KisGpuLayerDocument.*` | 作業版、GPU交換をまたぐCPU操作識別子、GPU用編集識別子と文書履歴。 |
| `libs/image/gpu/KisGpuEditSession.*` | 公開中と作成中の作業版、回復命令の一括採用と合算したCPU予算。 |

ブラシ生成器の入力・設定検査は同じ所有者の`validSample()`と`validSettings()`にあり、
ツール受付とブラシ生成が同じ値の制約を使う。
`kritatoolsgpustrokeinput`は`kritapaintinggpubrushstroke`に依存する。
構築は`LIBREPAINT_BUILD_GPU_DOCUMENT=ON`で有効になる。

## マウス・ペンの入力

`libs/tools/gpu/KisGpuPointerInput.*`は専用のQtウィンドウから、マウスの左ボタンと
ペン先・消しゴム側のイベントを受け取る。論理ウィンドウ座標を指定されたアフィン変換で
キャンバス座標へ戻し、ペンの筆圧を維持する。ペンから合成されたマウスイベントは同じ
描画の重複を生むため、元のペン入力だけを採用する。

押下時に対象レイヤー・ブラシ・選択範囲を固定し、文書が処理中の場合は有限のCPU待ち列で
開始を待つ。受付済み入力を順に`KisGpuStrokeInput`へ渡し、解放後に残る入力を処理して確定する。
表示先の活動終了も同じ確定要求を使用する。Escapeと有効なツール変更は所有する未確定編集を取消す。
入力待ち列の超過と不正な標本は操作を取消し、`inputRejected()`で理由を通知する。
他の利用者が開始した操作は取消さず、開始待ちのCPU値だけを解放する。

入力とウィンドウは解釈所有者より長く保持し、GUIスレッドから`poll()`でCPU入力を渡す。
GPU交換ではCPUの設定・入力待ち列・編集所有権を保持する。アプリケーション側が
`inputReady()`を再開と完了回収の契機へ接続し、具体的な描画入力のGPU処理を進める。
不正なツール設定と変換の更新は、現在の設定と操作を維持して拒否する。

`kritatoolsgpupointerinput`は具体的な描画入力とQt Guiへ依存する。
`KisGpuPointerInputTest`はQtイベントの座標・筆圧・消しゴム側を正規化入力の画像と比較し、
開始待ち、重複イベント、取消し、活動終了時の確定と拒否の原子性を検査する。
`hasPendingWork()`は未発行のイベント・形状と解放後の完了待ちの有無を返す。
`KisGpuStrokeInput::hasPendingWork()`は受付済み入力、空形状への差し替え、GPU結果の公開と
確定の処理待ちを返す。アプリケーション側は両所有者の処理待ちと表示の状態を使用し、
処理中は1ms、静止時と拒否時は16msの周期で進める。
外部取消しで編集識別子が古くなった入力も後処理の対象とし、現在の文書が所有する編集から
処理待ちを判定する。形状の破棄は同じGPU編集識別子に限り、後続の編集を維持する。

## クイックシェイプ

`libs/tools/kis_quick_shape.*`は直線・楕円の認識、直線の端点移動、楕円の拡縮・回転と正円化を所有する。
`kritatoolsquickshape`はQt Coreだけに依存し、GPU入力側へ認識・調整した形状値を渡す。
`KisGpuPointerInput`は有効な保持操作を認識器へ渡す。保持時間は500ms、移動の許容幅は
ウィンドウの3論理画素を現在の座標変換で文書座標へ換算する。
認識用の入力点はポインター待ち列と同じ設定上限で保持する。超過後は次の押下まで認識を終え、
受付済みの自由描画を継続する。認識済みの形状が描画入力の容量に収まらない場合も自由描画を保持する。

認識時の筆圧、ブラシ、選択と描画先を保持し、直線は両端の2点、楕円は256区間と閉じる1点を
正規化した描画入力へ渡す。形状調整は同じCPU編集識別子の`replace()`を使用する。
Shiftの押下は楕円と正円を切り替える。解放時の筆圧0は認識時の筆圧を維持し、
確定は表示中と同じ規則で生成したGPU版を採用する。
形状認識と調整のCPU値はGPU交換を挟んで存続する。

GPU編集画面の`Quick Shape`操作は初期状態で有効であり、描いたまま保持して直線・楕円へ変換する。
有効状態の切替とツール変更は未確定操作を取り消し、保存は最新形状を確定してから版を固定する。
`KisGpuPointerInputTest`は正規化入力との画像一致、選択付き質感・混色、筆圧、拡大率、
認識容量とGPU交換を検査する。`KisGpuDocumentWindowTest`は製品操作と保存・取消しを検査する。

## 入力と編集の契約

`begin(layer, configuration, target)`で画素またはマスクの操作を開始する。
設定、文書座標の切り詰め領域、選択の生成命令と質感のCPUマスクを固定する。
GPU資源はその操作のセッションで準備する。資源の準備失敗では操作を取り消して原因を返す。
設定の`brush.texture`はGPU参照を含むため受付を拒否し、CPU値の`texture`を使用する。

返した`Token`は文書のCPU操作識別子であり、同じ操作のGPU交換で維持する。
別文書、取消し済み、確定要求後の追加・差し替えと次の操作に対する古い入力は`Stale`になる。
レイヤーの非表示・ロックは文書の編集契約に従って拒否する。

- `append()`は全入力点を検査してから待ち列へ追加する。
- `replace()`は全入力点を検査してから待ち列を置き換える。次の回収で非公開の作業版を開始し、
  確定済みの下地から形状を分割生成する。従来のプレビューと回復値を保ち、全処理の成功後に
  完成した形状を一括公開する。作成中の形状は完成まで進め、次の候補は最新の一形状だけを保持する。
  これにより、一形状の処理時間より速い連続変更でも完成したプレビューを順次公開する。
  生成開始前の候補は直ちに置き換える。空形状は描画を必要とせず、作成中の候補も取り消して下地へ戻す。
- `poll()`は文書の非同期処理を進め、一回につき最大64入力点から一要求の印を生成する。
  混色は16印、通常描画はブラシ生成の上限まで進める。通常追加は完了した入力点を待ち列から除き、
  未完の区間は同じ入力点で継続する。高頻度入力の順序と筆圧を維持し、GPU発行をまとめる。
  差し替えは公開まで全入力点を保持する。次の候補があれば公開後に生成を開始し、
  追加入力は最新候補の末尾へ接続する。
- GPU容量・発行枠で拒否された入力は、待ち列と受理済み進行を維持する。
  `lastGpuError()`で原因を読み、容量や発行枠の回収後に再試行する。
- `commit()`は入力受付を終え、待ち列と差し替えの処理後に文書へ確定を渡す。
  文書が作業版を採用すると`Finished`になる。確定による再描画を伴わない。
- `cancel()`は所有する未確定操作だけを破棄する。文書への確定発行後は`Busy`を返す。
  所有者の破棄も未確定操作を取り消し、文書へ渡した確定は文書が完了させる。

待ち列の初期上限は1,024入力点、保持する質感・選択命令のCPU内容の初期上限は4MiBである。
待ち列超過は`QueueFull`として全要求を拒否し、受付済みの候補を保持する。
作成中の差し替えは処理済みの入力点も含め、最新候補と合計してこの上限内に収める。
最新候補の再差し替えは前の候補と追加入力を置き換える。生成開始前の差し替えは
待ち列全体を置き換えるため、新形状自身が上限内なら受付できる。
CPU回復値の予算不足は`RecoveryBudgetExceeded`として区別する。

## GPU交換と利用方法

利用側は文書、ツール入力所有者と表示所有者を同じ発行スレッドで操作する。
共有GPU所有者の直接接続した解放通知で`releaseGpu()`を呼ぶ。
この処理は進行値をCPUへ保持し、ブラシ生成器、選択・質感と編集セッションのGPU参照を解放する。
CPU設定、未処理入力、差し替え・確定要求と操作識別子を維持する。
未公開の差し替えは作成中のGPU版を破棄し、保持した全入力からの再生成を準備する。
次の候補があれば最新候補とその追加入力を採用し、古い候補の再生成を省く。

休止中の`poll()`は`Busy`を返す。文書を再開して回収を進めると、
新しいGPUセッション上に資源を準備し、受理済み進行から残りの入力を処理する。
差し替えは復元された従来のプレビューを保持し、最初の入力点から完成形を再生成して一括公開する。
休止・復元中の取消しはCPU操作識別子を検査して作業値だけを破棄する。
文書終了時は利用側が入力所有者を破棄してから文書を閉じる。

## 検証と保守

`KisGpuStrokeInputTest`は、複数入力点の発行集約、待ち列の全要求拒否、GPU予算不足からの再試行、
未処理形状の差し替え、プレビュー版の確定、選択・質感・混色付きのGPU交換、
活動中・休止中・復元中の取消しと破棄、別文書・古い操作の拒否を検査する。
連続した130点の差し替えは、入力中の完成形状の公開と最新形状の確定画像を検査する。
作成中・最新候補の容量合算と拒否時の候補保持、GPU交換時の最新候補・追加入力も検査する。
GPU交換の前後と連続描画の画素を完全一致で比較する。
通常描画ではCPU画素転送0を検査し、質感マスクの準備は明示的な資源転送として扱う。
構築・実GPU検査は[開発手順](DEVELOPMENT.md#gpu文書タイルの検証)に従う。
