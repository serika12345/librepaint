# ラスター編集の比較契約

## 目的と所有者

文書画素の保持場所や実行方式を変更するとき、利用者が得る色、透明度、選択範囲、
編集履歴を比較するための契約である。画素と編集履歴の所有者は `libs/image`、
合成演算と色プロファイルの所有者は `libs/pigment` と色空間プラグインである。

`libs/image/tests/KisRasterEditContractTest.cpp` は製品の `KisPaintDevice`、
`KisPainter`、`KisSelection`、`KisTransaction` を使い、固定値と編集前後の全画素を検査する。
基準入力は `libs/image/tests/data/raster_edit_contract.json` が所有する。
実行方式を置き換える側は同じ入力と期待値を使用する。

`libs/image/gpu/tests/KisGpuTileStoreTest.cpp`は同じJSONをGPUの単色描画と版どうしの画素合成へ渡し、
通常合成、消去、不透明度、一定被覆率を、領域外と元の版の保持を含めて比較する。
GPU資源と版の契約は[GPU文書タイルと版の契約](gpu-document-tiles.md)が所有する。

## 画素と入力

- 色空間は RGBA・各成分8ビット整数、プロファイルは同梱の
  [sRGB-elle-V2-srgbtrc.icc](../../krita/data/profiles/elles-icc-profiles/sRGB-elle-V2-srgbtrc.icc)。
- 基準入力の配列順は R・G・B・A。RGB値はアルファと独立した値とする。
  現行デバイスの B・G・R・A 配置への変換は試験の境界で行う。
- 通常合成、消去、不透明度、選択範囲の被覆率を固定した数値で指定する。
- 単色の長方形をブラシ印に相当する入力とし、生成乱数と非同期作業を持たない。
  入力元と描画先の座標をずらし、一画素、負座標、64画素境界をまたぐ領域を使用する。

この入力の範囲では全成分の完全一致を要求する。消去はRGB値を維持してアルファを減らす。
画素の読み取りと再編集の結果を維持するため、アルファが0になった画素のRGBも比較対象とする。
色変換、高ビット深度、筆圧や質感のある
ブラシはそれぞれの演算規則を含む画像契約を追加して受け入れる。

## 編集操作

| 操作 | 観測する結果 |
| --- | --- |
| 通常合成・消去 | 固定した期待画素と一致し、入力範囲外と選択範囲外の画素を維持する |
| レイヤー順序 | 下から順に合成し、半透明レイヤーを入れ替えると定めた色になる |
| 確定 | 複数の描画を一つの操作として採用する |
| Undo／Redo | 操作ごとの前後の全画素を正確に復元する |
| 取消し | 編集開始前の全画素と、確定済み履歴のRedo先を維持する |
| 未確定描画の差し替え | 元の占有範囲を復元し、新しい入力を直接描いた画像と一致する。確定結果をUndo一回で戻す |

未確定編集は確定済み画像から独立した作業版へ描画し、確定時に一つの操作として採用する。
CPU基準は `KisPaintDevice` のスナップショット複製を作業版として使用する。
現行の同一デバイスでは新しいトランザクションの開始時にRedo情報を破棄するため、
取消し可能な作業版が確定済み履歴へ及ぼす影響を、この分離で制御する。
比較対象は画素結果と履歴であり、作業版の物理的な複製方式は各実装が所有する。

試験は描画デバイス単位で同期実行する。描画キュー、操作の非同期完了通知、
実画面への提示、ファイル保存は、それぞれの所有者で比較条件を固定する。

## 基準値の出典と保守

JSONの期待値は、単色の通常合成と消去の計算から定めた固定値である。
編集履歴の期待値は、同じ試行で操作直前と確定直後に取得した全画素である。
差し替え後の画像は、新しい描画だけを実行した独立したデバイスと比較する。
いずれも維持する契約として扱う。

失敗時には入力名、座標、期待RGBA値と実際のRGBA値を出力する。
期待値を変更するときは、色や透明度の利用者にとっての意味、合成規則、
既存文書と履歴への影響を確認する。新しい入力には出典と比較精度を併記する。

## 利用方法

評価済みの開発環境から次を実行する。

```sh
./scripts/run-shared-test-env ./scripts/run-test KisRasterEditContractTest
```

試験は `kritaimage` とQt Testへリンクする。固定プロファイルを供給する
`kritalcmsengine` を構築依存とし、色空間の代替を検出して試験を失敗させる。
製品の画像・履歴実装を通るため、その所有ライブラリーの構築範囲を必要とする。

性能比較では画像契約の成立を先に確認し、小負荷・高負荷それぞれの中央値とP95、
CPU実働、GPU実行時間、論理転送量、メモリー使用量、入力から実表示までの時間を記録する。
実装方式の統合には、対象機能とOSの画像・入力・保存・回復契約、および対応する
性能受入れ条件を定める。
