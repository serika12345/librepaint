# L2Pの予測の区間をブラシと層の合成の経路で描く設計

## 目的と読者

この文書は、予測の線の予測の区間を、確定の線と同じブラシの処理と同じ層の合成の経路で描く設計を定める。読み手は[`l2p-prediction.md`](l2p-prediction.md)と[`l2p-predictor-design.md`](l2p-predictor-design.md)を読んだ開発者である。予測点の作り方は`l2p-predictor-design.md`の定めのまま変えない。この文書が置き換えるのは、予測点から画面の画素を作る部分である。

改善する指標は`l2p.residual_px`、`l2p.stop_overshoot_px`、`l2p.stop_retract_px`である。作業はCHARTERの「予測の線」の条文の範囲で行う。

## 要件

2026-11-21に利用者が次の要件を定めた。

- 予測の線は、どのブラシでも確定の線とほぼ同じ見た目で描く。鉛筆系の質感のあるブラシ、筆圧で太さや濃さが変わるブラシ、縁のぼけたブラシも対象である。
- 単色で太さが一定の線で代用する描き方は認めない。

このほか、`l2p-prediction.md`の次の定めを保つ。

- 予測は画素の正本、取り消しの履歴、保存の結果に影響させない。
- 予測の線で主指標を悪化させない。

## 現状と問題

2026-11-21までの実装では、`KisPredictionDecoration`が予測の線をキャンバスの装飾として描いていた。描き方は`KisPredictionLinePainter`のQPainterの線で、前景色、不透明度100%、ブラシの直径の一定の太さ、丸い端である。線は、最新の実点の少し前の起点から予測点までで、確定の線の表示前の末尾に重ねていた。

iPadで鉛筆系のブラシを速く動かしたときに、この線が確定の線と違う見た目で見えた。原因は次の3つである。

- 質感、筆圧による太さと濃さ、縁のぼかしが、予測の区間に出ない。
- 装飾は画面の最前面に描かれるため、層の不透明度、合成方法、上の層の透けが予測の区間にだけ効かない。
- 確定の線と重ねた区間では、半透明の確定の線の上に不透明な線が乗り、見た目が変わる。

## 一般的な方式

予測した入力を一時的に描き、実際の入力で置き換える方式では、予測の部分を確定の部分と同じ描画の処理で描く。`l2p-prediction.md`の「他のソフトと OS の方式」の表の出典で、次のことを確かめている。

- Windows Inkでは、低遅延の背景スレッドで描いた仮の線をストロークの完了で確定の線に置き換える。仮の線と確定の線は、同じ描画の属性で描かれる。
- iPadOSの予測タッチは、新しいイベントのたびに捨てる一時的なデータとして、同じ描画の処理に加えて描くよう案内されている。

LibrePaintでは、ブラシの点を作るブラシの処理と、層への合成の処理が分かれている。見た目を一致させるには、両方を確定の線と共有する必要がある。

## 設計の原則

1. 予測の区間は、確定の線の最後の状態の続きとして描く。点の間隔の累積、時刻、乱数の状態を、確定の線から写して使う。写した状態は予測の描画で進めるだけで、確定の線の状態は変えない。
2. 予測の区間は、更新のたびに前回のものを捨てて、すべて描き直す。前回の予測の上に描き足さない。半透明のブラシで濃さがずれ、外れた予測の跡が残るためである。
3. 予測の区間の画素は、確定の線と同じブラシの処理で作る。同じプリセットから作った別のブラシの処理を使う。
4. 予測の区間は、確定の線と同じ層の合成に載せる。画面の最前面には描かない。
5. 予測の描画に使う部品は、ストロークの開始時に作る。描画の途中で作り直さない。

## 構成

### 全体の流れ

1. GUIスレッドの`KisToolFreehand`が、今と同じく予測器から予測の折れ線を得る。
2. ツールは、折れ線をストロークのジョブとして`FreehandStrokeStrategy`へ送る。ジョブの種類は`Data::PREDICTION`である。中身は、予測点の文書座標と、最新の実点からの時間の列である。空の列は予測の消去を表す。
3. `FreehandStrokeStrategy`は、受け取った予測を最新のもの1つだけ保つ。ジョブの中では描かない。
4. 確定の線の点を層へ書き込んだ後の`issueSetDirtySignals`で、確定の線の範囲を先に`setDirty`する。その後、保っている予測と確定の線の状態を写し、並行して実行するジョブで予測を描く。ジョブの中で、描いた結果を層に渡し、前回の範囲と今回の範囲を`setDirty`する。予測を描くジョブが走っている間に次の更新が来たときは、そのジョブを飛ばし、次の更新で描く。

予測を描く頻度は、確定の線の表示の更新と同じになる。入力のイベントの頻度は、表示の更新より高い場合がある。描く回数を表示の更新に合わせると、予測を描く費用はイベントの数に比例しない。

### 予測の描画先

予測の描画先は、層ごとに1つの`KisPaintDevice`である。この文書では予測面と呼ぶ。予測面は、ストロークの描画先と同じ色空間で、ストロークの開始時に作る。

予測を描くたびに、次の手順をとる。

1. 予測の範囲Rを求める。Rは、確定の線の最後の点から予測点までの折れ線を、ブラシの点の大きさの最大値で膨らませた矩形である。
2. 予測面のRを、ストロークの描画先のRで上書きする。描画先は、間接描画のときは一時的な描画先、直接描画のときは層の画素である。コピーは`KisPainter::copyAreaOptimized`で行う。
3. ピクセルブラシでは、点を作る部品の列のうち、まだ層に書き込まれていない確定の線の点の仕事を写し、同じ情報から点を作り直す。作り直した点は、確定の線と同じ`bltFixed`で予測面に重ねる。列の仕事は点を作るための情報をすべて持つため、作り直した点は、後で層に書き込まれる点と同じ画素になる。これにより、作っている途中の点の分の隙間がなくなる。
4. 予測用の描き手で、予測面に予測の区間を描く。

予測の範囲は、`KisStrokePredictionCap`でブラシの直径の3倍以内に切られている。そのため、Rの大きさは、ブラシの直径のおよそ5倍の四方に収まる。コピーの費用は、この範囲の画素の数に比例する。キャンバスの大きさや層の数には比例しない。

### 予測用の描き手

`KisPainterBasedStrokeStrategy::initPainters`で確定の線の描き手を用意するときに、予測用の描き手を1つ作る。

- 描き手は予測面に対して`begin`する。選択範囲、`setupPainter`の設定、間接描画のときの合成方法と不透明度の上書きは、確定の線の描き手と同じにする。
- ブラシの処理は、同じプリセットから`setPaintOpPreset`で作る。
- 予測を描くたびに、確定の線の`KisFreehandStrokeInfo::dragDistance`を写した`KisDistanceInformation`を使う。乱数は、`FreehandStrokeStrategy`の`KisStrokeRandomSource`を写したものを使う。
- 予測の区間の`KisPaintInformation`は、確定の線の最後の点の値を元にする。位置は予測点、時刻は最後の点の時刻に予測点の時間を足した値とする。筆圧、傾き、回転は最後の点の値を保つ。
- ピクセルブラシは、ブラシの点を非同期に作る。予測用の描き手では、`doAsynchronousUpdate`が返すジョブを、予測の描画の中で順に実行し、すべての点を書き終えてから戻る。

予測点が実際の入力と一致した場合、予測の区間の画素は、後で確定の線が同じ区間に描く画素と一致する。点の間隔、時刻、乱数の状態を確定の線から写して使うためである。この性質を契約テストで確かめる。

### 層の合成

`KisPaintLayer`に、予測面と予測の範囲Rを持たせる。設定と解除は、`KisIndirectPaintingSupport`の書き込みの錠の中で行う。

`KisPaintLayer::copyOriginalToProjection`で、更新する範囲とRが重なる部分は、次のとおりに予測面を使う。

- 間接描画のとき：一時的な描画先の代わりに、予測面を`setupTemporaryPainter`の設定で合成する。
- 直接描画のとき：層の画素の代わりに、予測面を投影へコピーする。

Rの外は今と同じ処理である。予測面は投影にだけ使われ、層の画素、一時的な描画先、取り消しの履歴には入らない。

予測を描き直したときは、前回のRと今回のRの和を`setDirty`する。前回の予測が残る範囲は、予測面のない処理で描き直される。

### 消去

次の場合に、予測面とRを層から外し、前回のRを`setDirty`する。

- ツールが空の予測を送ったとき。停止後の期限、ペンを離したとき、予測の結果が無効なときである。
- ストロークを終えたとき、取り消したとき。`finishStrokeCallback`と`cancelStrokeCallback`で行う。

### 予測を使わない条件

次の条件では、予測を有効にしない。`KisStrokePredictionPolicy`に条件を足し、理由ごとに`prediction_policy`の値を分ける。

| 条件 | 理由 |
| --- | --- |
| マスクのブラシを持つプリセット | 確定の線は、マスクの描画先と色の描画先を別に持ち、`doMaskingBrushUpdates`で合成する。予測面を2つ持つ設計は、この文書の範囲の外とする |
| 鏡像の描画 | 鏡像の点は別の範囲に描かれ、Rが複数になる |
| 画面の折り返しの表示 | Rが画像の端で分かれる |
| 低解像度の先行表示 | 低解像度のストロークと本来の解像度のストロークが別に動き、予測面が2つ要る |
| 複数の描き手を使うツール | `numMaskedPainters`が2以上の場合である |

これらの条件で予測を使えるようにする作業は、計測でその条件の利用が多いと分かったときに別に設計する。

## 取り除くもの

次の部品は、この設計で使わなくなるため取り除く。

- `KisPredictionDecoration`と、ツールからそれを登録する処理
- `KisPredictionLinePainter`とその契約テスト
- `KisPredictionTestSwitches`とその契約テスト。外す条件である「予測の線の既定の有効化」と「取り込みの検査が色の検出を必要としないこと」は、2026-11-21の時点で満たしている

記録の印の`prediction_paint`は、予測面を描いた時点の印に置き換える。

## 記録の印

| 印 | 時点 | 値 |
| --- | --- | --- |
| `prediction_render_begin` | 予測面への描画を始めたとき | 位置に予測点、`extra`に予測の点の数 |
| `prediction_render_end` | 予測面への描画を終えたとき | 位置にRの幅と高さ、`extra`に描いたブラシの点の数 |

`prediction_render_end`と`prediction_render_begin`の時刻の差が、予測を描く費用である。

## 検証

### 契約テスト

1. 予測点を後の実際の入力と同じにしたとき、予測面のRの画素が、確定の線を描き終えた後の層の同じ範囲の画素と一致する。間接描画と直接描画の両方で確かめる。ブラシは、既定のプリセットから丸ブラシ1種と鉛筆系1種を使う。
2. 予測を何度描き直しても、ストロークを終えた後の層の画素と取り消しの履歴が、予測を送らなかった場合と一致する。
3. ストロークを終えた後と取り消した後に、層が予測面を持たない。
4. 予測を描き直したときに、前回のRと今回のRの和が`setDirty`される。
5. 層の不透明度50%と乗算の合成方法で、投影のRの画素が、予測面を層の画素として描いた場合と一致する。

### 計測

- 主指標：Linux X11とWindowsで、変更の前後を同じ入力で測る。悪化と判定する差は、シナリオの定めに従う。
- 予測を描く費用：`prediction_render_end`と`prediction_render_begin`の差の中央値とP95を、丸ブラシと鉛筆系のブラシで比べる。
- 見た目：iPadで鉛筆系のブラシを使い、画面収録で予測の区間と確定の線の画素を比べる。筆圧が変わった分の差は残る。

## 未確定事項とリスク

- 作り直す点の列を写した後、予測面へ層の画素を写すまでの間に、確定の線の点が層へ書き込まれる場合がある。この点は予測面に二重に入り、半透明のブラシでは濃くなる。列の取り出しの番号を写しの前後で比べ、違えば1回やり直す。やり直しでも違った回数は`prediction_pending_race`の印で数える。
- 予測を描く費用が表示の更新の間隔に対して大きい場合、確定の線の更新が遅れ、主指標が悪化する。費用の上限は計測の結果で決める。
- 基本の平滑化を使う場合、確定の線の最後の点は平滑化した位置で、予測点は平滑化前の入力から作られる。予測の区間の始まりで位置が跳ぶおそれがある。跳びの大きさを測り、問題になれば予測点にも同じ平滑化をかける。
- 予測の区間では最後の筆圧を保つため、筆圧が変わった分だけ、確定の線との差が出る。
