# L2P 停止後の行き過ぎの分析と修正方針

## 目的と範囲

この文書は、L2P（予測の線。設計は [`l2p-prediction.md`](l2p-prediction.md)）で、ペンを止めたときに線の端が止めた地点を超えてから戻って見える問題を整理し、測定、設計、合格条件の修正方針を定める。対象は次の 3 つである。

- 予測器 `libs/tools/KisStrokePrediction.cpp`
- 期限の処理 `libs/ui/tool/kis_tool_freehand.cc`（`updatePrediction`、`expirePrediction`、`clearPrediction`、`endStroke`）
- 取り込みの解析 `scripts/perf/pen-latency/capture_analyze.py`

読み手は、Issue #108 と `l2p-prediction.md` を読んだ開発者を想定する。この文書は方針を定める。コードと設定の変更は含まない。

## 用語

| 用語 | 意味 |
| --- | --- |
| 遅れ D | ペン先が動いてから、その位置の線が画面に出るまでの時間（ms）。予測なしの線の端とペン先の距離を、速さで割って求める |
| 予測の長さ H | 最後の実点から、予測の点を先へ置く時間（ms）。既定 16.7ms、範囲は 8〜25ms |
| 上限 k | 予測の移動量の上限を、ブラシの直径 d の何倍にするか。既定 3（`strokePredictionMaxMoveDiameters`） |
| 信頼度 c | 速さ、筆圧、減速の 3 つの係数の積（0〜1） |
| 期限 | 最後のイベントから、予測の折れ線を画面から消すまでの時間。現在は 20ms の単発タイマー（`gapResetMs`）で、履歴のリセットと同じ値を使う |
| 行き過ぎ | 線の端が、最後の注入位置を進行方向へ超えた距離（px） |
| 戻り | 連続するフレームで、線の端が進行方向と逆へ動いた距離（px） |
| 残りの距離 | ペン先より線の端が後ろにある距離（`l2p.residual_px`） |

## 現状と確認できた事実

### 実装（コードを読んで確認）

1. 予測の移動量は `速さ v × 信頼度 c × H` で、`k × d` を超えたら縮める（`KisStrokePrediction::predict`）。v は、12ms の窓の最初の点から最後の点への変位を経過時間で割った値である。
2. 減速の係数は、8ms と 20ms の窓の速さの比を、0.4 以下で 0、0.8 以上で 1 にする滑らかな階段である。
3. 実点が届くたびに、20ms の単発タイマーを張り直す。切れたら折れ線だけを消す。ペンを離したときは、`endPaint` の直後に `clearPrediction(1)` で消す。
4. 時刻は `event->time()`（整数 ms）である。同じ時刻のサンプルは、直前のサンプルを置き換える。
5. コミット `aea58464cd` が、上限 3 直径と `l2p.stop_overshoot_px`（`capture_analyze.py`）を足し、期限を固定の 20ms に戻した。

### 測定（`DECISIONS.md` の 2026-11-16 の行、Linux X11、H=16.7ms）

| 軌跡と項目 | 予測なし | 予測あり |
| --- | --- | --- |
| 3p0 の残りの距離、中央値 | 124.6px | 43.5px |
| 3p0 の残りの距離、p95 | 155px | 117px |
| varied の残りの距離、中央値 | 9.6px | 4.7px |
| varied の残りの距離、p95 | 99.8px | 28.8px |
| 3p0 急停止の先へ出た量、p95 | | 22.7px |
| 3p0 急停止の戻り `retract_px`、p95 | | 12px |

H を 25ms にした回は、3p0 の中央値が 47.6px で縮まず、先へ出た量の p95 が 59.3px に増えた。画面でも、止めた地点を超えてから戻って見える（利用者の指摘）。

コミット `cb9bacce60`（減速係数と到着間隔の期限）の測定は、動いている区間の行き過ぎが 22.7px から 2.6px に減り、戻りの p95 が 12px から 31px に増えたと報告された。この値の測定記録は保存されていない。再測するまで、参考値として扱う。

`aea58464cd` の後の `l2p.residual_px` と `l2p.stop_overshoot_px` の再測は、記録がない。

## 行き過ぎの機構

急停止では、最後のイベントの後にイベントが届かない。最後に描いた予測の折れ線が、期限が切れるまで画面に残る。

```
残る移動量 ≈ min(k × d, v × c × H)
見える時間 ≈ 期限 + フレームの位相
```

3p0 の速さは、約 4.9px/ms と推定する（推定の根拠は「試験と測定の限界」の 2）。信頼度 1、H=16.7ms の予測の移動量は約 82px で、直径 10px、k=3 の上限が先に効いて約 30px になる。

期限を 20ms から表示 1 周期（60Hz で 16.7ms）に縮めると、見える時間は 3.3ms 短くなる。残る移動量は変わらない。移動量を減らす手段は、H、k、信頼度の 3 つである。

減速の係数は、最後のサンプルまで等速の急停止で効かない。短い窓と長い窓の速さが等しく、比が 1 になるためである。速さが落ちながら止まるストロークでは、比が下がって信頼度が下がる。窓に入るサンプルは 2〜4 個で、時刻は 1ms 刻みのため、8ms の窓の速さに 12% 前後の誤差が乗る。等速の区間でも比が 0.8 の付近で振れ、信頼度が振動する可能性がある。戻り 31px の原因の候補である（推定。実験 (c) で確かめる）。

## 距離の目標と行き過ぎの目標の関係

予測の長さ H で予測する遅れ D の線は、定速で次の距離を持つ。

```
残りの距離 = max(0, D − H) × v
急停止の行き過ぎ ≈ H × v（上限なし、c=1 のとき）
```

残りを予測なしの 20% 以下にするには `H ≥ 0.8 D` が必要で、行き過ぎを 1 直径以下にするには `H ≤ d / v` が必要である。両方を満たすには `D ≤ d / (0.8 v)` になる。d=10px、v=4.9px/ms では `D ≤ 2.6ms` で、どの環境の遅れも満たさない。

上限 k × d を置くと、予測の効果は最大で k × d になる。

```
残りの距離の下限 = max(0, D × v − k × d)
```

D≈25.6ms、v≈4.9px/ms、k=3、d=10px の推定値では、下限は約 95px（予測なしの約 75%）である。この条件で「予測なしの 50% 以下」の目標は、上限と矛盾する。距離の目標は、上限と対にして決める。

## 試験と測定の限界

1. 試験軌跡は、定速のあとに静止（dwell）へ入る急停止だけである（`scripts/perf/pen-latency/trajectory.py`）。`speed_profiles` は区間ごとの定速で、減速の区間がない。人のストロークは減速して止まる。減速係数の効果も、人のペンで見える行き過ぎも、現在の試験では測れない。減速して止まる軌跡は、`DECISIONS.md` の 2026-11-16 の行が必要としたまま、作られていない。
2. 速さと遅れの換算が一致しない。3p0 の速さは、`l2p-prediction.md` が Surface で約 5.4px/ms とし、残りの距離の差（124.6 − 43.5 = 81.1px）を H=16.7ms で割ると約 4.9px/ms になる。`DECISIONS.md` の ms 換算（70.3 → 26.6ms）は 1.77px/ms を使い、この値と合わない。4.9px/ms を使うと、予測なしの遅れは約 25.6ms になる。換算の基準は 1 か所に固定する。
3. H=25ms の観測が、残り = (D − H) × v のモデルに合わない。モデルは約 3px を予測し、測定は 47.6px だった。予測の先端が `H × v` だけ先に出ていることを、取り込みを通さずに確かめる必要がある。
4. 停止の標本が少ない。停止は 1 本のストロークに 1 回で、`strokes=6`、`runs=5` では 30 標本である。p95 は 2 番目に大きい値に近い。
5. `l2p.settle_ms` は、窓が 100ms（`SETTLE_WINDOW_NS`）で、窓の中で収まらなかったストロークを集計から外す。収まった回だけの p95 は、窓の端に偏る。
6. テスト色ありの取り込みは、予測の線が変わるたびに画面が更新され、確定線を写すフレームが増える。確定線の距離が実際より大きく出る。`Pass.locate` を通した標本は、線の端が先へ出たフレームを捨てる。

## 修正方針

遅れそのものの短縮は主指標（CHARTER の目的）であり、予測の調整で代替しない。この方針は、予測の見え方（距離と外れの指標）を整える。

1. 試験と測定を直す（段階 0）。減速して止まる軌跡を足し、換算を 1 か所に定義し、停止の指標を足し、`aea58464cd` の前後と HEAD を再測する。
2. 予測器を、取り込みを通さずに評価する再生器を作る（段階 1）。入力は、記録した位置、イベント時刻、到着の時刻である。モデルは、予測器、期限のタイマー、フレーム時計（60Hz と 120Hz）を持つ。取り込みの再測は、最終の確認の 1 回にする。
3. 原因を切り分ける（段階 2）。
4. 予測器を、小さな変更を 1 つずつ直す（段階 3）。
   - 期限を、履歴のリセット（`gapResetMs`）と表示の期限に分ける。表示の期限は、フレーム単位でまとまって届く入力の合間に切れない長さを、再生器で決める。20ms から 16.7ms への短縮だけでは、残る移動量が変わらない。120Hz で 8.3ms にすると、まとまって届く入力の合間に期限が切れる危険がある。
   - 上限 k を、残りの距離と停止後の行き過ぎのトレードオフ曲線（H と k の組ごと）から決め直す。
   - 減速の係数に、信頼度の平滑化（30ms 程度の指数移動平均）を足すかを、実験 (c) の結果で決める。
   - ペンを離したときの消去（`endStroke` の `clearPrediction(1)`）は、離した瞬間の戻りを測り、悪化が示されたときだけ、確定線が最後の点に届いた次のフレームまで遅らせる。
5. 合格条件を改める（段階 4）。
6. 環境ごとの既定は、段階 3 の再測の後に、CHARTER の「悪化が示された環境では既定を無効にする」に照らして決める（段階 5）。配布は #108 の対策が終わるまで止めているため、既定の変更は今の測定の対象を隠す。
7. iPadOSとAndroidではOSの予測に委譲し、Windows、macOS、Linuxでは自前の予測器をKalmanフィルタへ高度化する。2026-11-19の利用者の決定で、設計は[`l2p-predictor-design.md`](l2p-predictor-design.md)にある。

## 実験

### (a) 到着遅れの内訳

目的は、注入からアプリの受信までの遅れと、受信から表示までの遅れを分けることである。

1. `KisLatencyProbe::mark` に、OS のイベント時刻を記録する。X11 は `QInputEvent::timestamp()`、Windows は `WM_POINTER` の `msg->time` を使う。
2. 既存の `qt_tablet_move`、`qt_mouse_move`、`move_compressed`、`compressed_dispatch`、`stroke_paint`、`paintgl_end`、`frame_swapped` と、`inject.csv` の注入時刻を、同じ時計で対応づける。
3. 各イベントで `受信 − 注入`、`stroke_paint − 受信`、`paintgl_end − stroke_paint`、`frame_swapped − paintgl_end` を出す。3p0 と varied を、予測なしで各 5 回測る（ウォームアップ 1 回）。

合格：到着遅れの p50 と p95 が、イベント単位とフレーム単位で出る。この結果は、遅れの短縮（L3 の Linux）の入力にもなる。

### (b) 停止中のイベント

目的は、停止をアプリが検出できるか、期限だけに頼る必要があるかを決めることである。

1. 試験軌跡は、停止中も 240Hz で同一位置の行を持つ。注入器がこの行をイベントとして送るか、アプリが受けるかは未確認で、`probe.csv` の停止中の `qt_*_move` の行数で確かめる。
2. 実機のペンとマウスが停止中にイベントを出すかは、合成入力で再現できない。Linux の実機で 10 本程度のストロークを描き、入力の列を記録する。この記録は、再生器の人のストロークの標本にも使う。

合格：停止中のイベント数が、入力の種類ごとの表になる。移動中のイベント間隔の p50 と p95 が出る。

### (c) 戻りの p95 が 12px から 31px に増えた原因

目的は、到着間隔に合わせた期限と減速係数のどちらが戻りを作ったかを分けることである。再生器で、次の 4 版を同じ入力で比べる。

| 版 | 減速係数 | 期限 |
| --- | --- | --- |
| 旧 | なし | 固定 20ms |
| 減速のみ | あり | 固定 20ms |
| 期限のみ | なし | 到着間隔 |
| 両方（`cb9bacce60`） | あり | 到着間隔 |

期限が動いている途中で切れた回数と、信頼度の振れ（等速区間で 20% 以上）を記録する。

合格：戻りの原因が、期限の途中消去か、減速係数の雑音かに特定できる。どちらの成分を残すかが決まる。

## 合格条件の改訂案

`l2p-prediction.md` の「合格の目安」を、次のように改める。

- 見え方（停止）は px で判定する。減速して止まる軌跡で、`l2p.stop_overshoot_px` の p95 がブラシの直径以下、`l2p.stop_retract_px` の p95 がブラシの直径以下とする（暫定。再測の後に決め直す）。急停止の軌跡は、上限 k × d 以下であることを構造上の限界として報告し、合否に使わない。
- px の判定を残す理由は、利用者が見ているのが戻りの大きさ（px）だからである。ms に直した行き過ぎは、H が 1 フレーム以下なら常に 1 フレーム以下になり、見えている大きさを検出できない。ms の指標は報告用に残す。
- 距離の目標（残りの距離の中央値が予測なしの何% 以下か）は、遅れの階級（25ms 未満、25〜35ms、35ms 超）ごとに置く。数値は、上限 k との対で、段階 3 のトレードオフ曲線を測った後に決める。遅れの階級は、実測した D で決める。同じ OS でも表示の経路で D が変わるためである。
- 停止の標本は、ストローク数を 12 本以上にし、p95 と並べて最大値とフレーム単位の分布を報告する。

## 指標の定義

最後の注入の時刻を `T_end`、位置を `x_end`、進行方向を `direction`、校正後の表示された線の端を `line_end(t)` とする。ストロークごとに 1 つの値を作り、中央値、p95、最大値を出す。

| 指標 | 定義 | 状態 |
| --- | --- | --- |
| `l2p.stop_overshoot_px` | `max(direction × (line_end(t) − x_end))`、`t` は `T_end` から 100ms まで | 実装済み（`aea58464cd`）。窓を 200ms に広げる |
| `l2p.stop_overshoot_ms` | `max(行き過ぎ px / v_end)`。`v_end` は停止前 12ms の中央速度。`v_end` が 0.2px/ms 未満のときは px だけ出す | 未実装 |
| `l2p.stop_retract_px` | ピークの後、連続フレームで進行方向と逆へ戻った量の最大値 | 未実装 |
| `l2p.stop_settle_ms` | ピークの後、行き過ぎが 1px 以下になるまでの時間。200ms で打ち切り、打ち切った回数を別に出す | `l2p.settle_ms` の置き換え |
| `l2p.stale_prediction_ms` | 最後の `prediction_update` から `prediction_clear` までの時間 | 未実装 |
| `l2p.prediction_clear_reason` | `prediction_clear` の理由（タイマー、実点、終了、離脱）の分布 | 理由の記録は実装済み。集計は未実装 |

取り込みの標本の選び方は、次のとおり修正する。

- `l2p_speed_groups` を、`Pass.locate` を通さない `l2p_tip_samples` に切り替える。速さは注入のサンプルから出す。
- テスト色ありでは、各注入サンプルの直後、次の注入サンプルまでの最後のフレームだけを選ぶ。
- テスト色の予測区間の端は `pred_xmax`、確定線は暗い画素の `dense_xmax` として別々に出す。
