# 無人ループ反復：Issue #89

あなたは無人ループの1反復を実行する。利用者は応答しない。質問・承認待ち・提案だけで終わることは失敗とみなす。
この反復で必ず実装を前進させ、コミットして push してから終了する。

## 目標

LibrePaint 全体を既定で GPU エンジン上で動かす（Issue #89 / 親 #87）。全部完成させる目標は動かさない。
現在は **フェーズA：ラフでよいので全体を GPU で動かす** を最優先する。品質磨き・性能・macOS/Metal・
環境間一致（#91）・旧経路の完全撤去はフェーズBで行う。

## 手順

1. `AGENTS.md` を読む。`gh issue view 89` で「ループ運用状態」と「全体稼働バックログ」を読む。
2. 作業ツリーに未コミット変更があれば、それを最初に仕上げてコミットする（前反復の途中作業）。
3. 最新の全体 verify 要約に失敗があれば、それを今回の最優先項目にする（修正、または下記の隔離）。
4. それ以外はバックログの未完了項目のうち最上位を選ぶ。大きすぎる場合はこの反復で終わる大きさに分割し、
   分割結果をバックログへ書き戻してから先頭を実装する。
5. 実装する。ラフでよい。動作する通常経路を広げることを、細部の完成度より優先する。
6. 増分ビルドと、変更に直結する局所試験で確認する：
   `build-incremental native build <target>`、`run-test <target> [regex]`。
   変更が広い場合は `verify-quick` も実行する。全体 `verify` はループ駆動が定期実行するので、自分では実行しない。
7. 論理単位ごとにコミットし、`git push origin HEAD:feature/issue-89-gpu-engine-rewrite` する。
8. Issue #89 本文を `gh issue edit 89 --body-file` で更新する（下記の規則）。
9. 時間の目安は1反復あたり90分。超えそうなら途中でもコミット・push・Issue 更新をして終了する。

## 進め方の規則

- 阻害（macOS 実機、外部依存、判断不能）に当たったら、Issue の「阻害」に1行記録して別の項目へ移る。止まらない。
- 5分以上かかる、または不安定な既存試験は、原因を短時間で直せなければ
  `QSKIP("LOOP-DEFERRED: <理由>")` で隔離し、Issue の「隔離した試験」に列挙する。期待値が古いだけの試験は直す。
- GPU 文書で未移行機能が旧 CPU 経路へ落ちることはフェーズAでは許容する。ただし網羅スモークで「CPU落ち」として
  計上し、バックログに残す。旧経路の撤去は、撤去で前進が止まらない範囲でその場で行い、残りは #103 へ記録する。
- 進捗指標は GPU 網羅スモークの結果（成功 / CPU落ち / 失敗 の件数）。存在すれば反復ごとに実行し、Issue に件数を記録する。
- 長時間コマンドには `timeout` を付ける。バックグラウンドに放置したプロセスを残さない。
- 禁止：force push、master や他ブランチへの push、履歴の書き換え、`build/agent-loop/` の削除、
  `scripts/agent-loop/` の無効化。
- `build/agent-loop/DONE` は、Issue #89 の完了条件がすべて満たされ、全体 verify が成功した時にだけ作成する。

## Issue 本文の更新規則

- 「ループ運用状態」節は10行以内。現在版、直近の成果、網羅スモークの件数、最新の verify 結果、阻害だけを書く。
- 試験の件数・秒数などの詳細はコミットメッセージに書き、Issue 本文には書かない。
- バックログ項目は完了したら `[x]` にし、新しく分かった作業は適切な位置へ追加する。完了した項目は
  10件を超えたら古い順に削除してよい（履歴は git にある）。
- 「目的と実現する状態」以下の設計節は、設計を変えた場合だけ短く更新する。
